# 发布与重启恢复：统一生命周期

当前网站、回滚网站、业务应用、邮件关闭状态和旧凭证是保护对象，不能用“进程 online”或首页 200 代替完整验收。原有发布/退役/预约激活规则保留；新增的重启恢复只能追加自己的严格类型，不能借它恢复任意异常或修改业务数据。

## 固定顺序

1. 整理已批准功能；逐文件清单覆盖真实在线版本到候选的全部变更。依赖、构建脚本不变。
2. 完整本地测试、真实浏览器和隔离 PM2 验证，再做 PR 与 main 的完整 CI。
3. 使用原可信引导安装精确 main 的工具源码。安装本身不改变流量、数据库或进程。
4. 独立预检系统启动身份。正常同一启动周期直接进入发布；真实服务器重启走下面的专用恢复状态机。普通 PM2 重启或其他配置漂移不能冒充系统重启。
5. 原网站发布路径：资源准入 → 受限构建 → 私有候选烟测 → 有凭证切换 → 保留原站回滚 → 两域名验证 → 两次预约任务自然周期 → 完成记录 → 独立只读审计。

## 重启恢复状态机

`未接纳 → 来源/配置复核 → 已记录意图 → 仅预约校验程序更新 → 进程配置持久化 → 新身份凭证提交 → 自然周期/公网审计 → 完成`

- 新旧 boot ID 必须不同。旧身份来自已验证的保留历史，不接受调用者提供的 PID、路径、env 或“已检查”标记。
- 只接纳相同且完整的 25 项注册集；按唯一名称与固定源码/端口绑定，不把重启后重新编号的 PM2 ID 当成原身份。
- 全部启动定义、业务环境、邮件关闭、站点与回滚源码、构建、配置和原门禁逐项核对。PM2 重建的 `unique_id` 单独验证，不能借此忽略其他环境字段。
- 已退役项保持停止，未退役项保持运行；不得复活旧网站、启动新服务或停止独立任务。
- 停止项在 PM2 恢复后仍保留历史 PID 文件路径和外层 UUID，只有嵌套的环境 UUID 可能重建；按真实停止语义验证，不能套用运行进程的新 ID/PID 路径规则。隔离验收主动制造 ID 空档，实际验证两类定义的重新编号和持久化。
- 必要的预约进程更新只改变校验程序来源；业务应用仍为原不可变应用。先保存意图和原配置，再进行一次身份绑定的 RPC，其他进程不变。
- 后续重启若校验程序本身已经兼容，直接保留实际恢复的进程，不再额外重启；只有明确需要更新校验程序时才走一次来源变更。新 boot ID 必须接续上一份凭证，不能复用旧启动身份。
- 旧证据目录、原 inode、源文件、失败记录和原门禁不覆盖。新凭证完整写齐并 fsync 后整体公布，再推进外部 head。
- 中断恢复只能核对本次拥有的意图、实际进程、持久配置和完整尾凭证；不能重新重启进程、重复迁移、删除锁或猜测成功。未执行且仍确实需要的进程配置持久化可在同一受审计意图下完成，不改变业务配置。
- 凭证提交后观察自然任务周期，验收程序不直接触发业务调度。校验失败保留现有网站和证据，不给未确认状态签发完成记录。

## 已生效的数据库修复

新增独立清单兼容版本，只接受已批准版本 `202611050213` 的精确历史 Git blob、原始执行凭证和当前数据库身份、函数体、ACL、注册记录。原 v1 规则仍拒绝这些 SQL 文件。

兼容记录不授权执行 SQL；接纳、切换前、切换后和独立审计均做只读复核。时区默认值的新增服务端模块是已审查、精确固定的只读地区映射，不改变原预约任务的业务应用或协议。

## 完成标准

工具测试通过不等于已部署；恢复原版不等于新功能上线。只有重启恢复完成、正式候选完成、保留窗口及持久配置正确、任务自然运行、完整公网验证和独立审计全部通过，才向用户报告完成。
