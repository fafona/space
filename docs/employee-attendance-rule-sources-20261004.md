# 员工考勤：三层候选规则来源与独立解析

日期：2026-10-04，第147批。承接[个人例外核准页面](employee-attendance-personal-rules-ui-20261004.md)。本批新增独立的三层规则读取及纯解析，不接管原工时、不新增正式判定，也没有部署。

## 本批范围

- 新增 `rule-sources-v1` 协议、负责人只读 RPC、默认关闭的 GET 接口及个人例外 → 考勤组 → 企业三层候选解析器。
- 单次只查一个考勤人员、最多7个当地自然日；不顺带读取打卡、订单、排班、请假或日历。
- 保留个人核准及撤回、原始归组区间及取消／结束、企业和组的区间前承接版本与区间内候选版本。读取不依赖“最新25条操作”，不能让较新的草稿遮住原来登记的候选规则。
- 逐字段区分未核准、未归组、未登记、显式继承、显式停用及数值0；不把缺失或超限当作企业默认值。
- 保留当前来源和逐层编号、版本、操作者、原时区、UTC边界与双身份依据。输出始终 `applied:false`、`formalReady:false`，不是历史固定快照。
- 尚无新页面／浏览器客户端。原 Sources128、两层解析、个人核准页面和既有 writer 保持不变；后续独立页面需使用本协议，不能将两次 HTTP 返回拼成一致来源。

## 一致性与授权

迁移130新增 `faolla_attendance_rule_sources_v1(jsonb,uuid)` 及其私有校验辅助函数，不增加业务表、索引、业务写入、回填或宽泛表锁。依赖064、124、127、129及各自前置，不依赖128。

服务端从已验证登录身份取得 actor，SQL再次校验当前商户负责人。按商户 → 设置 → 考勤人员 → 员工的顺序保留共享锁，随后读取三层来源；124／127／129的支持写入口均先取得同一设置行的排他更新锁，因此规则变更和缺失规则流的首次插入不能穿过这次读取。当前双身份变化也不得借旧个人账本继续解析。

这是**相对于支持写入口的锁定一致性**，不是数据库全局 MVCC 快照。一次 RPC 或相同 `readAt` 本身不提供该保证；直接管理数据库写入及不遵循契约的未来入口不能自动纳入保证。读锁也可能短暂阻挡同商户规则变更，真实规模仍需试点评估。

- 新接口：`GET /api/merchant-enterprise/attendance/rule-sources`，只接受 `siteId`、`workerId`、`fromDate`、`throughDate`。
- 独立开关 `FAOLLA_ATTENDANCE_RULE_SOURCES_ENABLED=1`，本批未配置，默认返回未开放。
- 沿用强身份、当前资格、规范入口／同源、按身份有界限流、私有不缓存和错误脱敏；不接受客户端 actor 或写命令。
- 暂停模块仍可按当前授权读取；模块状态不是写权限。停用人员可保留同身份来源，但纯解析会阻断，而非显示正常候选。
- 已有个人账本在查询区间没有记录时，也必须匹配当前员工和认证身份；换绑后明确拒绝，不自动回落企业规则。

## 有界与日期语义

- 归组候选、规则流／所有登记版本合计、个人候选分别有100条上限，检测到第101条返回相应 `limited:true` 和空集合，不截出前100条冒充完整结果。归组超限还阻断依赖它的规则集合。
- 个人索引预筛保留查询开始前816小时。该保守边界依据129最多31个当地自然日及时间边界算法推导；用实际小时而不是受数据库会话DST影响的日历天。候选数量可能保守超限，不能据此断言精确重叠条数。
- 响应最多1 MiB，严格限定字段、普通JSON树、顺序、身份、版本与时间戳；不执行输入 getter，不放过稀疏数组或额外字段。
- 所有应用区间为UTC半开区间。结束时刻不再使用个人例外；撤回的核准仍显示原依据，但不参与有效候选或多余切段。
- 切段覆盖归组、候选发布及个人开始／结束边界，理论上限501段，不默默截断。超限、身份不一致、停用、来源缺失及重叠歧义均阻断；即使上层数值可能覆盖下层，也不伪造一条完整来源链。
- 当前时区决定查询自然日范围，保存时区决定原记录UTC边界；跨夜、DST、跳过日期和2100年末边界不能统一按24小时处理。

### 本批发现与修正依据

1. 新fixture把26次旧规则写入放入一条SQL，触发10秒超时。拆为独立语句，未修改原业务函数或超时。
2. 上限fixture逐次回放195次完整旧写入存在大量重复历史校验。一次长回放经本机目录、端口、应用名与精确PID核验后取消，按原包装器回滚、恢复并停止。随后改成基于本轮真实RPC生成的核准／撤回模板，在自有schema的单回滚事务内分22步追加195条**合成上限行**，全部原有约束、触发器和外键保持启用。这些行不是195次真实负责人核准操作；正常6条操作仍通过真实RPC产生。
3. 精简fixture后，真实100条来源读取仍触发10秒超时，栈定位于新130逐条调用129收据校验，重复扫描 `pg_timezone_names`。这是新读取路径的已复现问题，不能用延长超时或减少检查掩盖。仅新130增加本次RPC局部校验复用，旧129及其成功写入路径不变；最终同模板100条实读约1.33秒通过，结果及限制见上。

新增私有辅助函数仅复用成功校验的命令主体，以及以 `(开始或结束、时区、日期)` 为键的原日期函数结果。命令主体只排除操作编号、预期版本和理由，这三项完整约束每次重新核验；撤回目标版本与本次预期版本的关系也每次检查。命令主体变化时仍调用129完整校验器，日期变化时仍调用原二分边界算法，不复制另一套时间算法。

每条snapshot、前序记录、双身份、目标关系和完整复制字段仍单独检查，首尾账本校验保留。缓存只在一次RPC局部存在，不写表／GUC／全局状态，不从HTTP接收或返回；辅助函数对PUBLIC、anon、authenticated、service_role均不可直接执行。该优化针对重复上下文；不能据同模板上限样本推断任意100个不同时区／日期／版本组合或生产负载都在相同耗时内完成。
