# 超级后台：账号与模块访问分析方案

状态：已完成四轮本地增量实现及针对性自动验证，未部署、未修改生产数据。实际覆盖范围、未完成项与启用前条件见 `account-traffic-analytics-phase-1-2026-09-23.md`、`account-traffic-analytics-phase-2-2026-09-23.md`、`account-traffic-analytics-phase-3-2026-09-23.md` 和 `account-traffic-analytics-phase-4-2026-09-23.md`；第四轮 UI 浏览器验收、生产构建及兼容新增统计表/接口的发布通道尚未完成。本文其余部分仍为完整目标方案，不代表全部完成。

## 统计对象与现状

- 以内容所属账号为归属维度；商户账号下按站点、模块、具体对象分层。
  个人账号若拥有公开名片，也使用同一归属模型；不等于跟踪所有实名访客。
- `src/lib/analytics.ts` 目前主要采集 page_view/contact_click 等简化事件，
  浏览器直接写 page_events。联系方式点击只有渠道，缺少完整归属。
- `src/app/api/super-admin/merchant-accounts/route-handler.ts` 读取最新 1000 条
  全站事件，再按 site:<id>:... 汇总；所谓 today 是滚动 24 小时，不是自然日。
  因此当前列表不是可靠的完整月报，不能在此基础上直接增加几列。
- 没有采集过的历史来源、单张名片和访客维度不能追溯重建。旧记录中确有
  归属和时间的信息可单列为“旧版浏览记录”，不假装具备新统计的精度。

## 后台界面

用户列表保留简洁摘要：近 30 天浏览量、估算独立访客、有效转化、趋势、
“访问分析”按钮。明细独立按需加载，不拖慢用户列表和登录。

账号分析页面：总览 / 模块分析 / 名片分析 / 来源渠道 / 行为转化 /
设备与地域 / 事件明细。全局筛选账号、站点、时间、模块、对象、来源、
访问环境；支持排名、上一等长周期对比、趋势和权限受控的 CSV 导出。

名片分析必须一张一行，使用稳定 cardId，显示名称、缩略图、状态、浏览量、
访客估计、入口、主要操作与趋势。改名不会拆成新对象；历史数据保留对象
标识和当时名称。不同投放渠道使用独立 campaign/link ID，不靠名称归并。

## 模块与事件

| 模块 | 浏览对象 | 操作与结果 |
| --- | --- | --- |
| 网站 | 官网首页、子页面、页面入口/出口 | 页面切换、按钮点击、有效停留、滚动深度 |
| 产品 | 分类、列表、具体产品详情 | 搜索、筛选、详情打开、加购、发起下单、后端确认订单 |
| 预约 | 预约入口、项目/服务、选择日期/时段 | 开始填写、尝试提交、后端确认成功、取消；不采集填写内容 |
| 名片 | 每张公开联系卡；公开图片被查看另列 | 官网、电话、邮件、WhatsApp、微信复制、地图、Google评价、联系人文件下载 |
| 优惠券 | 列表与每张券详情 | 点击领取、后端确认领取、实际核销 |
| 会员 | 入会页面、会员介绍入口 | 发起申请、后端确认入会；不采集会员私密页面内容 |
| 投票/活动 | 每项活动/投票页面 | 参与按钮、后端确认提交；不采集投票选项等内容 |
| 会话 | 联系/咨询入口 | 打开会话、后端确认首次咨询；不采集聊天内容 |

曝光与浏览分开：产品列表加载不能算每个产品都被看过；卡片进入可视区域
才可记曝光，打开详情才记详情浏览。广告/消息预览器获取名片图片不算真人
打开名片。编辑器预览、后台页面、健康检查不进入公开访问指标。

## 访问方式必须拆成独立维度

1. 来源：Faolla 首页、站内目录/搜索、其他商户、其他名片、搜索引擎、
   社交/消息/邮件、外部网站、已标记推广活动、直接或未知。
2. 入口媒介：普通链接、分享链接、专用二维码链接、NFC 专用链接、广告链接。
3. 浏览环境：普通浏览器、微信内置浏览器等可识别环境；手机/电脑/平板，
   操作系统、浏览器家族、语言。环境不等于来源，更不等于扫码方式。
4. 投放位置：每个账号可创建渠道链接，标记门店海报、桌牌、包装、员工、
   展会、社交账号或广告活动，使用稳定渠道 ID 比较效果。

归因证据单列为“已标记链接 / 来路域名推断 / 未知”。不存完整来路查询串，
避免意外保存登录令牌、邮箱等。首访来源与本次访问来源分开；保留账号内
跨模块导航链，例如名片→产品→预约，但不默认跨账号关联同一访客。

边界：

- 同一个未标记 URL，无论手输、复制、相机扫码还是长按识别，服务端通常
  无法区分。标记为二维码的链接被复制访问，也只能称“二维码渠道访问”。
- 现有二维码编码外部官网直达 URL 时，Faolla 无法观测目标页打开。不得
  悄悄修改既有扫码目的地；可另行选择新统计短链接，或在外部网站接入采集。
- 官网按钮可统计出站点击，但不能自动证明外部网站到达/订单完成。
- 联系人文件下载不等于系统通讯录保存成功；拨号点击不等于接通；分享
  按钮不等于实际发送。成功类事件以本系统可验证的后端结果为准。

## 指标口径

- PV：去重后的公开页面/详情浏览事件，不是所有 HTTP 请求。
- UV：在允许的识别范围内估算独立浏览器访客，不称为真实人数。拒绝非必要
  识别或无法识别时显示覆盖范围/不可用，不伪造跨会话去重。
- 会话：建议 30 分钟无操作结束，仅在适用的匿名标识范围内计算。
- 总览 UV 对同一范围去重，不能把各模块 UV 相加。PV 与动作点击也不混加。
- 有效停留只累计前台可见且活跃时间；采用有限检查点，不按秒上报。页面
  关闭可能丢失最后一段，显示估算口径，不承诺秒级准确。
- 漏斗：曝光→详情→意向操作→后端成功，注明分母、去重范围和时间窗口。
  不把客户端提交按钮直接标记为预约成功/订单成功。
- 今日、昨日、自然月按明确报表时区计算（默认 Europe/Madrid，处理夏令时）；
  近 7/30 天与自然月分开。历史总量、未知、不可用、确认为零必须区分。
- 已识别爬虫、疑似异常、管理员自访/编辑预览分开标记，原始与清洗后数量
  可核对；不承诺检测出全部机器人。显示数据更新时间、覆盖开始日期、延迟。

## 采集与存储原则

- 建独立版本化采集接口/事件表与每日汇总，不破坏既有 page_events 数据。
  前端携带稳定 eventId 去重；服务端记时间、解析对象归属、限制字段和值域。
  客户端声称的账号 ID/对象 ID 不直接作为可信归属。
- 公开采集限制体积、频率、事件种类和标签数量，预防刷量与高基数膨胀；
  客户端分析不能保证完全防伪，要区分可验证业务结果和浏览器上报。
- 批量异步发送，失败丢弃/有限重试，永不阻塞页面、预约或保存。后端业务
  成功事件应幂等采集，不因分析服务不可用使业务提交失败。
- 明细分页、服务端聚合，禁止再下载“最新若干条”充当完整统计。缓存按
  账号和筛选条件隔离；异步导出并防 CSV 公式注入。
- 明细建议保留 90 天、按日汇总 25 个月，实际按流量、存储和隐私要求确认；
  定期归档/清理，保留聚合完整性与删除流程，不无限积累日志。
- 默认不收集姓名、手机号、表单内容、聊天正文、精确位置、设备指纹；
  不持久存储原始 IP 用于分析。地域只做可得且有覆盖标记的粗粒度汇总。
  非必要访客识别、跨访问行为分析按用户选择启用，并提供退出/撤回机制。
- 报表接口严格要求超级管理员认证及有效白名单设备，不直接给普通登录
  用户查询事件表。细分小样本地域/行为数据应限制展示，避免反向识别人。

## 实施顺序与验收

1. 基础：确定口径、独立采集/汇总、权限、旧记录隔离与“近30天”准确统计。
2. 页面：账号总览、网站/产品/预约/名片独立统计，每张名片对象级报表。
3. 来源：专用投放链接、二维码渠道、浏览环境、来源可信度；不改旧二维码。
4. 行为：模块间漏斗、后端成功事件、停留/回访估计、导出与保留策略。

至少验证：跨账号归属攻击被拒绝；普通用户不能读报表；重试不重复计数；
产品曝光/详情不混算；每张名片独立；名片改名不丢历史；未知来源不误判；
微信环境不自动算微信分享；后台/预加载不算公开浏览；夏令时边界正确；
UV 汇总不直接相加；超出 1000 条仍完整统计；后端成功事件幂等；统计服务
失败不影响业务；未同意识别不产生持久访客追踪；明细保留期限可执行；
现有二维码目的地/账号白名单/旧数据均保持不变。

数据库迁移、生产采集开关与正式上线另行安排；本次仅整理方案。
