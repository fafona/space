## 使用路径与准确口径

负责人在既有“单员工资料核查”读取来源后，从新增“计划关联核对”明确选择一个本次来源中的排班，再点击“读取计划关联核对”。初始不选择、不自动请求；不按姓名、相邻时间或补正后时间自动配班。排班来源超限或员工身份未就绪时不发起详情读取。

[新页面](../src/components/enterprise/MerchantAttendancePlanCoverage.tsx)经[客户端](../src/lib/merchantAttendancePlanCoverageClient.ts)、[GET处理器](../src/app/api/merchant-enterprise/attendance/plan-coverage/route-handler.ts)及[服务](../src/lib/merchantAttendancePlanCoverage.server.ts)，一次GET只调用一次[139 RPC](../scripts/supabase-migrations/202610050139_merchant_attendance_plan_coverage.sql)。139在同一事务取得明确关联集合，并逐条复用[138完整班次读取](../scripts/supabase-migrations/202610050138_merchant_attendance_shift_check.sql)，没有多个HTTP回复拼接成同次观察。

[纯算法](../src/lib/merchantAttendancePlanCoverage.ts)版本为`explicit-closed-spans-v1`，只计算**已保存明确关联的闭合上下班跨度**：

| 项目 | 本批口径 |
| --- | --- |
| 原始／核定 | 原始打卡与最新已批准核定分别计算；无批准替换的班次沿用原始，不叠加两套结果。 |
| 覆盖 | 各可信闭合跨度与排班半开区间求交，再求并集；包含休息，不是净工作时长。 |
| 重复相交 | 单列重叠区间及来源编号；合并覆盖不重复计时，不自动删除核定或原记录。 |
| 空档 | 仅表示本次明确关联集合未覆盖的区间，不等于缺勤，不包含其他通路、请假或漏卡申报。 |
| 开放／待核验 | 未结束终点保持未知，不用asOf补下班；待核验关联不并入可信覆盖，仍保留来源说明。 |
| 取消／未来 | 区分当时已取消和关联后取消；未来、进行中、已取消等状态不生成最终空档清单。 |
| 零长度／贴边 | 保留原记录；零长度和恰好接触端点不产生正长度覆盖。先比较整数微秒，再格式化显示。 |

无关联、缺少可靠发布依据、存在待核验或未结束关联、计划尚未结束或已取消时，空档为“当前不能给出”，不把未知记成0。仍可展示已经取得的可信闭合跨度；这些数值不是全渠道完整出勤率。补正即使移出排班，仍按原slot关系返回，不自动转绑。跨夜与DST计算只用保存的UTC端点，不按当前时区数据重写历史。

子资料保留各自的`readAt/asOf`，外层返回`readStartedAt/readCompletedAt`；不篡改成同一瞬间，也不称历史封账快照。父资料只提供授权选择锚点，详情可以反映后来的取消、下班或批准修订，但不能替换原排班的编号、发布版本、地点、时区或UTC端点。

## 授权、开关与有界实现

- 后端`FAOLLA_ATTENDANCE_PLAN_COVERAGE_ENABLED`与前端`NEXT_PUBLIC_FAOLLA_ATTENDANCE_PLAN_COVERAGE_ENABLED`均仅在精确值`1`时开放，默认关闭。没有新的写入开关或对原打卡资格的隐式授权。
- GET只接受`siteId/workerId/slotId`。服务端独立核验当前负责人，即使关联集合为空也不能跳过授权；merchant→settings→worker→employee共享锁保留到事务结束，不升级成写锁。
- 原slot的employee必须匹配当前员工。存在136发布依据时双身份必须一致；真正缺少136依据可作为不完整来源显示。已有关联的员工／Auth不匹配会拒绝，不能凭同名合并。当前身份仍匹配时，停用和考勤模块暂停不抹掉历史只读权限。
- 按`merchant_id/slot_id/start_event_id`枚举，先探测11条；最多10个关联原班次，合计最多2002条原事件，RPC及HTTP均限制1MiB。超限整体拒绝，不展示前10条或部分事件冒充完整集合。
- 服务端逐条验证138的原固定来源字节／SHA和完整资料后，仅传紧凑投影。浏览器不接收`sourceText`，不引入服务端Node校验器，也不自行重算规则来源。
- 读取为`private, no-store`，不轮询、不自动重试、不导出、不写浏览器存储。客户端严格校验UTF-8、重复JSON键、成功／错误响应形状及大小，12秒期限覆盖请求与解析。
- 换排班、父资料引用、员工／负责人、请求函数，或页面隐藏／卸载时清除旧结果；迟到响应不能恢复。恢复可见不会自动重查。后取消可显示，已取消状态不能退回未取消。

139只新增一个独立只读函数和关系表上的部分索引`attendance_shift_schedule_slot_idx`：`(merchant_id,slot_id,start_event_id) WHERE slot_id IS NOT NULL`，没有新增业务表、留存副本或修改旧writer。

索引采用分阶段`CREATE INDEX CONCURRENTLY`，不能给整份迁移额外包单一事务。创建前后核验归属表、键、谓词、默认算子类／排序规则、有效和就绪状态。正确合法的中断遗留索引可以重用；错误／无效索引明确失败，未完成注册，不自动删除或修复。索引有存储及后续写入维护成本，不宣称零成本或已完成生产容量验证。

旧Sources协议、打卡、本人选班、规则发布、个人例外、补正、工资和CSV均不改。既有[SourcesPanel](../src/components/enterprise/MerchantAttendanceSourcesPanel.tsx)仅新增独立入口及必要准确说明；原子区的含义不变。
