# 员工考勤：负责人原班次依据核查（第156批）

## 实现范围

155新增按原始上班事件读取保存依据的只读后端，但尚无负责人操作入口。本批在既有“员工考勤资料核查”中追加独立、默认关闭的区域：从当前查询已经返回的原始班次选择，明确读取一个原班次依据。没有批量发现、轮询、预取、写入、导出或浏览器持久保存。

原始班次起点是唯一查询锚点。已批准补正的起止时间与原始时间分列，补正不能重新套用当前规则；整段漏卡申报没有原始上班事件，不伪造编号。缺失、待核验和已核验明确区分；已核验仅表示服务器核对了原规则依据，不表示考勤正常、正式排班关联成立或工资已经计算。

## 浏览器与服务器边界

155原文校验器使用Node SHA-256，不能直接引入浏览器。因此新增独立、只读的紧凑展示接口，复用155的严格服务端核验后投影展示字段；旧接口、SQL、保存原文、打卡通路和工时计算不改。紧凑接口不传整份原文，浏览器核对展示协议、查询锚点与完整字段来源链；页面标明“服务端核验”，不声称浏览器重新验证原文哈希或签名。

新前端开关为 `NEXT_PUBLIC_FAOLLA_ATTENDANCE_SHIFT_RULE_BINDING_READ_ENABLED`；服务端复用155的 `FAOLLA_ATTENDANCE_SHIFT_RULE_BINDING_READ_ENABLED`。两者均默认关闭，本批不配置开关或生产部署。现有资料核查入口及其资格也必须成立；开放读取不授予打卡、审批或绑定写入权限。

新接口仍核验规范域名、同源请求、强认证、企业资格、限流和当前负责人；暂停考勤不妨碍仍有权限的只读核查。当前身份换绑时拒绝读取，不按姓名合并。当前姓名及状态可变化，历史规则保存时区、地点时区、来源版本和原作者保持各自含义。

切换班次、查询资料、人员、负责人、请求会话，或隐藏、关闭、卸载后，旧详情清除、未完成请求作废；返回须明确重读。读取有总超时、正文大小、UTF-8及严格JSON校验，迟到回复不能覆盖新的选择。
