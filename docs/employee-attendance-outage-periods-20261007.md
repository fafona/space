# 员工考勤：故障恢复与周期核对接入（215）

日期：2026-10-07。沿用用户已批准的210范围，只将相关故障纳入新周期送审／确认／封存的来源核对。**本批限定代码与本地数据库整合验收已完成，尚未部署，也不是C24或P1整体完成。**

## 规则与兼容边界

- 只取同一商户、同一员工档案且声明的UTC半开时段与周期重叠的故障；边界刚好相接不算重叠。相关候选最多100条，先限定员工和时段再计数，之后逐条检查保存的员工／Auth双身份，不通过过滤旧身份隐瞒换绑记录。
- 未提出核对结果、未本人确认、有异议、重开或依据已变化，均不能按“已核完”处理。是否解决沿用178真实当前依据、精确结果版本、本人确认和负责人结案规则。
- 未核完相关故障禁止新送审。来源变化也会使旧版本无法继续确认／封存；核完后需重新预览和保存版本，并由本人重新确认。原请假、补正等完整但待处理资料仍按旧规则允许送审，不扩大本次限制。
- 已封存周期不自动解封。新增声明、来源变化或新版本不会重写旧归档、旧确认、原编号回执；固定版本导出与原编号恢复不重新采集今天的资料。
- 无相关故障时，不新增空上下文或强制升级来源版本，保留旧canonical正文、指纹及原阻断项。员工预览沿用旧的`unresolved_review`提示，不冒充负责人完成了正式核查。
- 不新增计时来源、不重算旧工时、不补造打卡、不修改旧迁移或真实用户数据。

## 实现

新增179迁移，增加一个私有上下文助手和一个按商户／员工／声明UTC范围查询的普通表达式索引。仅替换三个现有函数：固定周期来源允许首份归档为v4；外层来源追加故障快照；新送审增加`unresolved_outage`门槛。其余旧函数、恢复及封存分支由逐字差异测试约束。

来源v4的`context.outages`保存11个固定字段；每条状态保存6个固定字段，不纳入观察时间或调用者能力开关。提议保存结构化证据，不重复携带原始sourceText。TS验证确切结构、身份、顺序、版本、UTC重叠、响应关系和当前解决条件；只复制一份去掉新字段的视图供旧v1～v3校验器使用，实际归档保留完整原始v4来源。

周期页面增加明确的故障限制提示、保存内容标题及状态显示；固定CSV和打印沿用现有完整导出机制与文本转义。未新增故障登记／核对操作页，也未接入新的生产API。

迁移仍在既有事务运行器内，锁等待限3秒；不改变部署运行器或绕过保护。未来无维护发布前仍需核查线上表量和锁影响，不能把本地小表建索引通过当作生产无阻塞证明。
