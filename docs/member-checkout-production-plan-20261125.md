## 3. A：持久结果存储与正式安装凭证

### 位置与权限

- 提议专用根目录为 `/var/lib/faolla-checkout/installations/`，最终绝对路径、owner 与文件系统需在正式准备时核准；目前未创建，也不声称已经纳入备份。
- 不在 `/tmp`、release 目录、`.next`、public、上传区或历史版本清理目录保存正式凭证。清理规则必须明确排除此根目录。
- 安装记录由受信安装身份持有，目录 0700、证据文件 0600；应用进程不因需要结算而获得安装记录写权限。
- 每次操作独立 operation ID；固定来源／目标／安装前快照／完整登记／版本对／步骤集合在首次 DDL 前绑定，不能从数据库可变名称重新选择目录。
- locator 与结果文件分开交付：记录批准 operation、可信根目录身份、来源／目标／seal 摘要及登记版本，不含密码、JWT 或签名钥匙。locator 的存放、独立备份和恢复者权限也必须核准，不能只把绝对路径打印出来就称已交付。

### 提交顺序与恢复

1. 验证已批准 operation、完整来源、版本预留、持久根目录和独立 locator；检查磁盘／备份／当前与回滚保留条件。
2. 开事务并取得既有安装互斥，核对当次获批窗口内的真实目标、完整登记及安装前元数据；漂移拒绝，不自动刷新基线。
3. 只执行准确新来源；旧六份前置仅核对，不重放；新购买、Stripe、邮件和新后台任务保持关闭。
4. 生成 prepared 结果，排他创建文件、校验 owner／mode／无链接、文件 fsync、目录 fsync，再关闭重读。先完成这一步，再提交数据库。
5. 同一数据库事务登记准确来源和 seal 摘要对，COMMIT。
6. 用新连接及独立文件核对原结果；成功后追加独立确认记录与 locator 确认，不覆盖 prepared 或失败证据。

COMMIT 派发后的错误、超时或进程退出不代表没提交。先核对原 operation，不盲目重跑；缺文件、缺 locator、双登记缺一、结构／目标漂移均停止。不能从数据库摘要重造已经丢失的可信文件。

正式 seal 需要新的来源身份及完整真实基线，不借用 `999999990047／999999990048`、六条 CI seal 或旧五来源包。正式版本号目前仍未预留；来源批准不能仅靠重算 hash 获得。

### 必须实际演练

- 完成写文件后、登记前、COMMIT 前后分别终止独立安装进程，重新启动恢复器；保留原文件和失败记录。
- 恢复时零 DDL 重放、业务快照不变；重复执行只确认同一原结果。
- 目录替换、符号／硬链接、权限变化、文件截断、磁盘满、写入冲突和丢证据拒绝。
- 用独立备份恢复凭证及 locator 后再次核对；若数据库恢复到新集群导致目标身份变化，必须取得新目标绑定批准，不能静默改旧 seal。
- 目录 fsync 不冒充已验证主机掉电或云盘持久性。实际存储与备份覆盖未确认前，这部分仍不算正式就绪。

## 4. B：短期凭据，无需重启的交付方案

### 推荐路径：独立签发端 → 私有原子文件 → 应用按派发读取

- 签发端只接受固定用途，角色固定 `faolla_checkout_runtime`，不接受调用者提供任意 role／claims／算法；不为应用提供通用签名接口。
- 签名钥匙留在独立批准的可信签发边界，不导出给 Codex、应用环境、日志、构建、前端或 journal；不为此轮换整个项目签名钥匙。
- 签发端位置、实际算法／key ID、issuer／audience 要按正式网关配置核对，不凭 CI 的合成 HS256 夹具推定生产配置；目前尚未配置该签发端。
- 令牌 TTL 初始建议 5 分钟、剩余 2 分钟前续发，均为待隔离验证的参数。实际派发仍须保留既有 12 秒请求预算及保守时钟余量，不延长 HTTP 写入期限。
- 仅交付短期令牌的私有文件，建议位于 `/run/faolla-checkout/`；该位置是临时运行交付，不是需要长期保存的安装凭证。重启后没有有效令牌就保持新结算不可用，不能读回磁盘上的旧长期能力。
- 发行端按固定文件名写同目录临时文件、fsync 后原子替换，再同步目录；读端对路径、父目录、owner／group／mode、普通文件／单链接／有界 UTF-8 JSON、用途、角色、期限做检查。
- 文件权限按实际 writer／reader UID／GID 设计。分离用户时可以是 writer 拥有且 app group 仅读的 0750 目录／0640 文件，app 不得写目录或文件；不是一律写成 0600 却假定另一个 UID 能读。若应用以 root 运行，只能保证不主动交付签名钥匙，不能宣称该文件能隔离被攻破的 root；更强的身份隔离需单独评估、批准。
- 应用的新增文件模式默认关闭；现有 ENV 模式保持原行为。文件模式启用后缺失／损坏／过期即拒绝，不回退 ENV、用户头或 service role。每次真正派发前异步有界读取有效令牌，不以长时间缓存掩盖删除／轮换。
- 文件读取与 HTTP 共用原总期限；晚到的文件读取不得再触发 POST。一次业务调用只派发一次，不因换令牌而自动重发未知结果的财务请求。

应用当前 JWT 解码只是配置 sanity，不是签名验证或用户认证。角色切换还需要准确数据库登录角色被授予该角色，不能只看 JWT 声明。[PostgREST 14 身份与角色](https://docs.postgrest.org/en/v14/references/auth.html)

`exp` 到期必须拒绝；换一个文件不会天然撤销仍在有效期内的旧签名令牌，这是基于无状态验证模型的推论。正常续发允许有界重叠；紧急撤销另走数据库 EXECUTE／网关成员关系的准确撤销，不能冒充正常“停止新购买”。[JWT 的期限要求](https://www.rfc-editor.org/rfc/rfc7519.html#section-4.1.4)、[PostgREST JWT 模型](https://docs.postgrest.org/en/v14/references/auth.html#jwt-authentication)

### 同一应用进程必须通过的验收

1. 不重启、不 reload Next.js，至少跨三轮合成短期令牌；新请求读到新代次，原排队请求在派发前重新核对。
2. 并发读取遇到原子替换只能得到完整旧版或新版；无半文件、无令牌泄露、无重复财务 POST。
3. 过期、未生效、错误角色、错误签名／audience／配置要求的 issuer、错误 owner／权限／链接、文件缺失与读取超时均拒绝；普通登录和旧业务仍工作。
4. 签发端暂时失败时，只有仍满足完整派发余量的有效令牌可用；到期后拒绝，不延长 TTL、不借 service role。
5. 正常停新购买仍允许已批准的原单读取／重放／取消；紧急撤能力可能一起阻断原单，须明确告警与恢复操作。
6. 日志、异常、浏览器包、请求返回、journal 与测试报告均不包含令牌／钥匙；生产探测不以提交真实订单来验证。

这部分会改变应用文件。旧 2971 文件指纹、已完成构建及旧源包不得刷新或冒充覆盖新代码；采用独立应用修订／来源绑定、新候选与对应完整 CI，保留旧代码和旧断言的准确固定副本。

## 5. C：正式来源、权限与完整网关隔离

- 形成新的正式安装包身份，绑定批准的应用修订、原 32 提案／runtime／047 适配和四条叠加的准确来源，以及完整批准的安装前基线；旧包原样保留。
- 不扩大业务 SQL、普通 API 或公开旧写入器权限。runtime 为 NOLOGIN／NOINHERIT，仅固定 dispatcher；executor 为 NOLOGIN／NOINHERIT、明确需要 BYPASSRLS，但不能成为 runtime 的父角色，不能直接拿到 047 原内部写入器的执行权。
- 只对经过配置证明的实际网关数据库登录角色增加 runtime 成员关系；不向 anon／authenticated／service_role 或其它继承者批量授予。观察到某个会话角色不等于完成配置证明。
- 完整演练必须按批准的真实版本固定 Auth／Kong／PostgREST 等镜像和路由／校验方式；现有 path-only 代理验收不能标为 Kong 已通过。缺的配置身份只能另行获批最小读取，不能输出完整环境或钥匙。
- 用合成身份／数据实际验证用户登录、能力签名／期限／角色边界、积分／券／库存／原单、过期／撤销、暂停、取消未知应答和恢复；旧成功路径与旧收银 pending 保留。
- 完整安装前新读属于以后安装窗口中的明确授权，不复用已结束的单次只读许可；漂移时退出并报告，不将真实状态塞进旧 CI 基线。
- 正式安装涉及 schema、函数、角色／授权和迁移登记变化，必须明确批准。安装计划逐条列出 DML；不得夹带客户行变更、商户开关、价格配置或无关旧迁移。

## 6. D：无维护上线与试点

1. 所有范围保持空／关闭，保留当前网站、独立后台任务及稳定回滚；先完成结构安装与能力连通的非财务校验。
2. 建立结算专属新候选和兼容回滚。回退保留新增结构，不倒放旧迁移、不 DROP 数据；不能任意换回不认识新账本的历史版本。
3. 完整 PR／准确提交 CI、受限构建、门禁／烟测、版本保留和恢复检查按原流程执行，不复用旧二维码通道或旧构建。
4. 候选切流后复核公开路由、普通登录／预约／订单／会话；不以写真实财务数据作烟测，不启用邮件或 Stripe。
5. 用户另定一个明确商户试点，核对其项目价格／积分、有效券、退分／退券政策和权限；范围初始为空，不自动沿用官网账号作为结算试点。
6. 正常暂停只停止新购买，保留原单服务；紧急撤能力和交通回退分别有独立证据，不清空原单或隐藏未知结果。
