# 考勤规则：带来源的两层候选解析

日期：2026-10-04，第144批。承接[143批来源核查](employee-attendance-sources-20261004.md)，在既有只读核查页新增企业／考勤组候选规则解析。**个人例外尚未接入，历史来源未封存；这是候选对照，不是正式规则应用或考勤异常结论。没有部署。**

## 已实现的限定范围

- 沿用负责人、单员工、最多7个当地日期的来源读取。新增解析纯函数与展示组件，不增加API请求、写入命令、迁移或业务表。
- 按当前归组区间及候选发布的UTC边界切分查询范围，使用起点包含、终点不含的区间。在边界时刻采用新候选发布，不以当前时区重算保存的发布边界，不用固定24小时推算日期。
- 已取消的归组不参与选择；已结束的归组只覆盖其保存的最终结束边界。每段只允许一个归属；即使重叠的两条属于同一组也不能任选第一条。
- 每项先对照组层，再对照企业层。明确数值保留0；明确停用不向下继承；继承才继续下一层；两层都没有设置时显示“未配置（不是0）”。
- 选最新适用的完整发布快照，而不是最新账本操作或旧版中最近的非空值。新版本改为继承后转向企业层，不回捞旧组版本的数值。
- 已知完整规则流在某时点没有发布，与规则流缺失分别处理：前者保留“该时点无候选发布”的依据，后者停止该段解析；不把未知当作继承。
- 展示归组编号／版本，以及候选发布编号、发布版本、账本版本、保存时区、设置／组版本、原操作人及记录时间。历史版本不要求等于当前版本，也不被当前名称或设置覆盖。
- 每次最多301个时间段，每页最多10段，翻页只切换本地结果，不重新查询；新来源到来、隐藏／关闭／换人清除后不会保留旧结果页。

## 停止解析与安全边界

归组或规则来源截断、来源身份变化、当前人员档案停用时，整个查询只显示未解析状态。归属重叠、当前组停用、必要流缺失时，对相应时间段停止解析，不退回企业规则掩盖未知情况。当前组停用不是历史期间均停用的证明，因此提示核查，不伪造历史判断。

排班、请假或日历来源截断继续明确显示；这些资料不直接改变本次两层规则对照，也不使结果获得正式判断资格。请假批准不在此自动免除排班，日历不成为法定节假日依据。

输出始终为 `applied: false`、`formalReady: false`，固定保留个人例外未接入、历史来源未固定、候选未应用三项限制。无迟到／早退／缺勤结论，无通知，无工时、工资、假期余额或打卡拦截变更。

解析器只接收既有严格解析后的 `SourcesResult`，是内部纯计算，不是身份授权或HTTP校验边界。额外的内部一致性检查不能代替原来源读取的当前授权和完整性核验。结果为独立的深冻结对象，不修改或共享可变输入；错误只使新增解析区显示不可用，不移除可核查的原始来源。
