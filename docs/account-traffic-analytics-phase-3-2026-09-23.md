# 账号访问分析：第三阶段（渠道标签与受控导出）

状态：本地实现与验收；未部署、未执行生产迁移、未修改用户名片或线上配置。

## 已实现

- 入口媒介独立于 referrer 来源及浏览器环境：`unknown / qr / share / nfc / ad`。只读取一个合法 `faolla_medium` 参数；重复或未知参数不猜测。采集接口拒绝任意字符串，旧版客户端缺少字段时按 unknown 处理。
- 普通网站 Provider、投票联系卡 Provider 和独立普通联系卡脚本均上报当前页面的渠道标签。不存完整页面 URL、查询参数或用户填写内容，不使用存储、访客标识或持久会话。
- 原始记录、每日汇总键和清理保护检查同时纳入 medium；后台新增“链接渠道（浏览＋曝光，依据链接标签）”，来源/浏览器维度保持独立。
- 后台可生成单独的渠道链接；只接受 HTTPS 的 faolla.com 或其子域名，保留原路径、查询参数和 fragment。仅生成/复制文本，不保存或替换已有名片链接，不重新生成旧二维码。没有服务器跳转器或持久 campaign 记录。
- 新增 CSV：本次筛选范围汇总、趋势、来源/渠道/设备/动作，加上当前页最多 50 项对象。明确标注范围、模块、对象 ID、查询时刻、匹配对象总数、偏移及实际导出行数；不称为全量明细导出。
- CSV 仍由相同的超级后台域名/会话/受信设备授权保护；单次 RPC 生成一致的报表快照，不跨页反复查询形成不一致结果。响应 no-store/private，附件文件名只含已验证 ID/整数，固定 CSV Content-Type、nosniff。
- CSV 全字段引号转义、UTF-8 BOM，防公开名片名称等内容造成公式注入；错误响应不保存成文件。前端有超时、禁重复点击和错误状态。

## 不能宣称已实现的部分

- “二维码渠道”是 URL 标签，不证明用户实际相机扫码。链接复制后仍带标签，用户也可更改标签。微信内置浏览器不等于微信分享。
- 未标记的既有二维码仍未知；外部官网直达和自定义域名暂不由生成器支持。无跨页面渠道继承、跨账号跟踪或首访归因。
- 投票联系卡 `/card/...` 的现有 307 跳转重新构造目的 URL，可能丢弃渠道参数；本轮不改变该已工作路径。需给**最终 `/share/business-card?...` 页面地址**打标签，不能把普通短入口贴标签后承诺完整透传。界面提示填写最终地址。
- 生成器只校验 URL 格式和域名，不证明目标已发布、已接入统计或属于当前账号；实际采集归属仍由服务器签名的公开资源决定，不能靠链接参数改变。
- 没有逐活动/门店/桌牌 campaign、全量异步导出、UV/会话/时长、后端确认转化等；第一/二阶段未覆盖的个人名片、特殊入口及其他模块仍待做。
