# 候选来源留存／恢复页面：第150批

日期：2026-10-04。承接[第149批留存后端](employee-attendance-rule-captures-20261004.md)。本批仅新增独立操作界面与浏览器客户端，默认关闭；不改旧打卡、审批、规则写入、计算或131账本，不部署、不操作真实资料。

## 操作范围

1. 在负责人考勤人员行打开独立「来源留存」入口；入口关闭时不加载操作页或发起请求。
2. 选择最多7个企业当地日期，明确读取当前来源作人员、双身份及日期核对。来源不完整或人员未启用时不能新留存。
3. 输入理由、确认目标与范围后，先保存当前标签页的待确认原编号／原命令，再提交。服务器重新读取来源；提交时结果可能与先前预览不同，并非把屏幕内容上传归档。
4. 显示已验证回执摘要：编号、原文摘要、来源大小、日期、原读取／本次观察／留存时间。不把归档重新送进当前时区或规则解析器，不声称这是实际历史采用版本。
5. 成功回复丢失时保留原编号；明确查询原号恢复。只有用户明确要求原号重试、先GET仍没有回执且当前模块开放，才按同一编号／原内容POST；不自动重发、换号或轮询。

留存不改变实际打卡、工时、工资或周期状态。完整但无法正式解析的候选来源，仍可能被作为本次观察保存；保存成功不等于业务规则有效或已应用。

## 轻量恢复与边界

- 标签页sessionStorage只留一个按企业／负责人／人员隔离的小槽：待确认命令及最近成功编号，不存完整来源正文、持久草稿或无限历史。
- 同槽采用原字节核对后替换；旧实例不能清除新实例写入的待确认操作。不可读、损坏或写后读回不一致时停止新提交，不静默覆盖。
- 手动输入已知UUID可GET读取对应回执。这里不是全部历史列表或检索；关闭标签页或清站点后最近编号不保证保留，丢失编号的服务端有界发现入口仍另做。
- 首次新提交若得到已验证、确定未写入的有限错误，可结束本次待确认；此前发生未知结果的原号重试不能据另一条拒绝响应断言前一条请求没成功，仍保留原号。GET未找到本身不能清掉待确认操作。
- 隐藏、pagehide、切企业／账号／人员、替换认证请求函数、父级撤权或卸载立即取消在途展示；迟到响应不能回显，也不能消费旧pending。恢复可见不自动请求。
- 修改日期使旧核对结果失效；离开未提交输入前提示。撤权和强制卸载不会被草稿提示阻挡。确认框返回后还须核验同一可见页面代次、同一核对结果和可提交状态。
- 默认关闭前端 `NEXT_PUBLIC_FAOLLA_ATTENDANCE_RULE_CAPTURES_ENABLED`；预核对依赖130服务端 `FAOLLA_ATTENDANCE_RULE_SOURCES_ENABLED`，保存／原号读取依赖131服务端 `FAOLLA_ATTENDANCE_RULE_CAPTURES_ENABLED`。不要求同时开启旧打卡写入或三层预览的前端入口。本批不配置任何开关。
