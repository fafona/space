# 考勤任职结束／再入职：第196批本地实现记录

2026-10-06。用户已确认[第195批边界第2、3节](employee-attendance-employment-lifecycle-boundary-20261006.md)，本批实现限定负责人、同一worker／employee／Auth的任职结束与再入职。默认关闭，未部署、未操作生产或真实员工资料。这里管理的是考勤任职区间，不代替劳动合同终止、工资结算或法律手续。

本批限定工作包已完成本地验收，包括最后回执故障回滚、4组新并发及6组实际父页面验收；不是195全部边界矩阵或整个考勤计划完成。

## 已实现范围

- 负责人从考勤配置全局入口或人员行明确读取任职依据、阻断和分页历史。结束／再入职不授予其他管理权限，也不按姓名、工号或相近身份合并人员。
- 正式结束须已有身份精确匹配且仍暂停的193代际，worker为停用状态。无原始事件可视为off；有事件则必须是本人`clock_out`，且事件ID、序列、动作及employee归属与暂停时保存的尾事件完全相同。暂停后即使通过原113合法收尾，尾事件变化仍阻断，不能据此假称已满足193恢复链。
- 在锁内按企业当前时区重新计算办理日，只关闭当前唯一开放期，结束日包含当天；不追溯、不预约未来结束。日期或worker、employee、settings、任职版本、暂停代际变化须重读，不沿用过期预览。
- 未结束且有效的排班、待审／已批准请假和工作安排均列为阻断，包括进行中及今天稍后的事项。须回到原业务入口显式处置；原流程不允许取消时保持阻断，不暗增取消权限。已完全过去的历史待审明确标为未统计，不冒充零项。
- 再入职须同一身份及受控结束依据，新增期从服务器企业当天开始，严格晚于上一期结束日，因此不能同日结束后再入职。旧区间不修改，新期不自动激活账号或worker。
- 新期建立后仍须走193明确恢复；原`was_active=false`仍保持false。受控任职已结束、链不合法或当前新开放期尚未覆盖企业今天时，即使原false也不能解除暂停。旧PIN和两类委托继续失效，后续签发须另行明确操作。

未自动补下班、重置事件序列、修改旧工时、裁剪申请、取消排班、改写规则引用或重算归档。紧急账号停用仍独立可用，不因未下班或待审事项被阻止。

## 数据、接口和兼容接线

新增迁移`202610060166_merchant_attendance_employment_lifecycle.sql`，单事务、3秒锁等待预算；仅新增私有追加表`merchant_attendance_employment_operations`。原任职表只在成功结束时关闭当前开放期，或成功再入职时追加新期；同时推进worker和settings版本。不可变操作保存真实操作者、完整命令及紧凑回执，RLS、禁止改写／删除／截断、service-only RPC与私有helper权限均单独核验。不回填历史操作。

两个经批准的旧路径适配保留原入口OID和私有原文副本：

1. `faolla_attendance_admin_v1`只替换原单开放期的历史护栏判断。新账本证明的同身份受控链允许多期；已结束人员可修改非任职资料但不能启用。未经新流程证明的旧异常多期仍拒绝。原owner授权、操作重放优先、设置CAS、身份不可换、开放原始班次和地点检查保留。
2. `faolla_attendance_account_detail_v1`在原193资格外增加`employment_closed`阻断，检查受控链及当前有效新开放期，置于`was_active`分支之外。未使用新生命周期的普通193暂停不改语义；原恢复／状态回执及原号入口不改。

新API为`/api/merchant-enterprise/attendance/employment-lifecycle`，调用`faolla_attendance_employment_lifecycle_v1`。GET只有`list/detail/history/recover`；POST只有明确`close/rejoin`，服务端真实Auth进入SQL，UI的owner标签不代替权限判断。正常读写在merchant、settings、worker、employee的既有顺序内核验；新写先持settings UPDATE，再取得worker锁，不反向升级settings。

读取边界为人员／操作历史每页25条及额外1条探针，单人最多100段任职及199笔受控操作，尚未结束事项合计100条及额外1条探针。超限阻断，不以部分清单声明资格完整。请求上限8 KiB，回复上限128 KiB；日期来自SQL，保存事项时区仅作标签，不让浏览器当前时区库重新解释历史端点。

成功原号重放核对原操作者及完整命令，不重复写区间或推进版本。独立已知原号恢复GET在当前owner权限、开关或商户可用性变化后仍可核对原操作者的最小保存回执，不能读取他人原号或发起新操作。已匹配回执才解除本地待确认；明确、严格验证的无写入POST拒绝可解除本次精确意图，网络失联、503、损坏响应、同名普通错误和GET查无回执均不作为失败证明，不自动重POST。
