## 2. 建议一次批准的完整工作包

员工明确选择出差／外勤／远程 → 预览时间与冲突 → 提交 → 当前负责人批准或驳回 → 本人查询结果及历史；待审可撤回，已批准只能追加有理由的取消或新的替代申请。

同时接入异常人工核对和新周期保存版本，避免先交付一个与考勤核对脱节的申请簿，再重复改造。该联动仅提供工作安排上下文，不能冒充到岗、实际工时或自动免迟到的证据。

### 拟采用的首版政策（尚未生效）

1. **只认可安排，不证明工作已发生。** 不生成打卡、不更改旧工时、工资、请假余额，不绕过定位、现场码或PIN，不阻止真实上班／下班。
2. **固定企业时区。** 申请保存当时采用的时区、明确UTC起止和员工双身份；手机旅行时区不改变归属。不存在的当地时间拒绝，重复时间要求明确偏移。
3. **补申请默认最近30天。** 使用新功能自己的明确配置，不借用补正或请假政策；从企业当地提交日期核对申请起始日期。该默认值是产品建议，不宣称法律或行业要求。涉及封存的申请另受重开要求限制。
4. **重叠提示，不自动合并。** 与本人其他工作安排、请假及排班重叠时展示类型和区间；负责人明确确认冲突及处理理由，不能重复计时，也不读取其他企业的私人记录。
5. **审批首版仅当前企业负责人。** 员工不能自批；没有合适的第二审批人时明确提示暂不能批准，不暗加自确认例外。委托审批另属C03，不顺带开通。
6. **封存前处理相关待审。** 同员工、实际相关时段的待审工作安排进入新周期核对上下文并阻止新封存；已经封存的相关时段，新提交、批准或取消需先按既有流程明确重开。无关人员／区间不受影响。真实打卡不受此门禁限制。
7. **独立权限，默认关闭。** 新增申请权限，不自动授予旧角色，不自动启用真实商户；读取、审批和导出仍逐次重新授权。
