# 员工考勤：单班次原规则依据只读桥（第155批）

## 范围与原因

154的时间对照只能证明区间相交，Sources128没有返回原班次绑定。新桥精确读取一个原始上班事件及133保存的依据，使后续消费者能够核对原事件、地点、历史员工双身份和原规则版本。它不把当前规则反推到旧班次，也不把补正后的开始时间当作新绑定起点。

本批限定后端接口与隔离验收，尚未增加负责人操作页面，也没有正式排班关联、迟到／早退或工资计算消费者。既有Sources128、四条打卡通路、规则writer、工时与导出均不修改。没有生产访问、开关配置或部署。

## 只读契约

- 查询只有商户、考勤档案和原始上班事件三个编号；没有客户端作者、员工身份、来源JSON、当前规则或批量全表参数。
- 每次核对当前负责人，锁定当前设置、档案和员工身份后，再按同商户／同档案的事件主键读取。普通员工、其他负责人、错档案、非上班事件和身份不一致均不能借此读取依据。
- 已有绑定须逐项对应原事件的操作编号、序号、地点、时间、事件时区及员工身份；PIN请求身份为空是原设计，不得误判成其他登录通路。
- `verified`表示这份绑定来源通过核验，不等于考勤正常、所有字段有值或工资已计算。原规则的0、停用和未配置保持不同含义。
- `unverified`保留原固定原因且无来源正文；`missing`明确没有绑定，不补写、不回填。旧事件没有保存登录身份时，不能借当前登录身份声称历史双身份已证。
- 原来源正文最多64KiB，按原UTF-8字节及SHA-256核验，不重新序列化后验哈希。源编号可能因去重早于本班次；原发布作者也可能不同于现在的负责人。
- 使用原已保存UTC边界、版本及三层字段来源链；不调用当前时区规则重新换算，不读取当前规则流来替换历史。企业规则时区和原打卡地点时区不必相同。
- 服务器及响应解析器拒绝缺键、多键、重复JSON键、篡改哈希、不一致字段链或作用范围。外层响应另设256KiB上限，容纳源文本JSON转义，不把64KiB原文上限误用为整个HTTP上限。
- 当前身份不变时，停用档案／员工和暂停新考勤仍可由当前负责人只读核查；此读取不重新授予打卡或修改权限。

## 发布边界

新增135候选迁移，只增加三个私有校验函数、一个只读RPC及最小执行授权，不增加表、索引或业务数据。依赖064／133及其前置；134是本次真实新开班验收的前置，不是读取旧已存绑定所需的写入授权。

新GET入口默认关闭，服务器开关为 `FAOLLA_ATTENDANCE_SHIFT_RULE_BINDING_READ_ENABLED`。它和153写入开关相互独立；安装迁移或开放读取不等于开通新绑定写入。真实发布仍须非维护候选验证、明确试点及回滚核对。

- 使用实际未来规则写入模板生成受约束的合成过去来源，并非自然跨日见证。认证／资格为合成注入、数据库传输为本地SQL桥；本批不重复四种打卡全链路，也不是实际Auth、PostgREST、Next／代理、手机或容量验收。

SHA-256解析器采用同步Node实现并只用于服务端；未来页面只能类型导入或使用另行验证的浏览器协议，不能直接引入Node运行时代码。
