# 故障备用纸表与单声明资料交接（第220批）

## 交付范围

本批在实际故障工作区增加两个只读工具，默认关闭、仅完成本地合成验收，未部署、未访问生产或真实员工。继续遵守用户选择：先完成本地验收，再准备真实账号和手机试点。

- **空白备用表**：单人两页，没有预填姓名、账号或企业资料，生成时零业务请求。填写商户／地点、同一纸表编号、当地起止日期、IANA时区与两端UTC偏移、工号、原操作编号／未知、事实说明；本人声明与负责人代录分别留名。恢复核对清单与资料签收独立，不把签名当作在线本人确认。
- **单声明交接单**：仅当前企业负责人，在明确确认资料保管责任后打印。每次依次重新读取176声明与178当前核对结果，不复用屏幕上的旧DTO；两次读取分别标明时刻，不冒称跨请求原子快照。停用新写、`canWrite=false`不妨碍服务器允许的合法只读核验。

入口复用 `MerchantAttendanceOutageLauncher` → `MerchantAttendanceOutagePanel`，新增独立懒加载打印组件。`NEXT_PUBLIC_FAOLLA_ATTENDANCE_OUTAGE_PRINT_ENABLED=1`为单独候选开关；不设置则不展示。打印开关开启时，即使故障新写入口关闭，也能进入备用表与资料核对；旧三参数入口判断保持。

本批不新增API、SQL、权限角色、工时写入或打印后台服务，不修改已有周期报表打印模块。

## 资料含义与边界

交接单明确区分：保存的原声明、读取时的当前状态、保存的负责人提案、本人回应、最新历史动作，以及提案当时采用的来源。是否当前核完只认178返回的当前状态，不把旧 `resolve` 动作当作仍有效结案。来源变化后，历史端点仍标明为保存值，不能冒充重新核验的当前端点。

声明与提案交叉绑定商户、负责人、逐人声明、人员／员工身份、申报区间及原号／原通道；不要求不同保存时点的人员版本或暂停代次相等。最多10个来源全部列出，超限拒绝，不能静默截断。打印人员／员工业务编号，不额外查询员工目录或猜测姓名；不输出Auth UUID、凭据、原始证据JSON、SHA或所有历史页。

空白表应在系统可用时提前打印，或按浏览器支持另存。完全停机时不能保证打开未缓存网页。纸表、交接单均不是可信离线打卡、工资认可、申请期限豁免、本人确认、结案或周期封存；不回填原始事件、不重复计时、不自动解除旧封存。

## 权限、生命周期与失败处理

含已保存资料的打印只允许 `owner`。两个GET复用既有受验证身份与严格公共协议；仅接受精确200、JSON、无重定向、正确当前作用域与完整结构。成功响应上限2MiB、错误体4KiB，拒绝重复JSON键、无效UTF-8和非预期状态。单请求最多12秒，整体从发起起固定30秒、不续期；即使底层忽略abort，也不能晚到交付。

切换企业／账号／声明／请求器、导航输入变化、关闭、隐藏、pagehide及卸载会撤销旧生命周期。父页草稿与三类精确pending键实时参与检查：存在未知或坏字节、存储不可读也阻断，不扫描其他账号、不删除编号、不自动POST或重试。首次页面扫描后的同页新增pending也能挡住正在等待的打印。

新打印适配器只使用短期离屏iframe，`sandbox="allow-same-origin allow-modals"`，文档CSP禁止脚本、外部资源、表单和嵌套内容；核对文档种类及当前生命周期后才调用打印。afterprint、取消或到期移除iframe。进入交付后再取消或超时，保守提示结果不确定、核对是否已出纸或另存；不会声称能收回已打印文件。浏览器打印对话框可能阻塞JS，30秒检查不能承诺同步撤销已进入浏览器或实体打印机的任务。

独立审查发现并修正了两处新增实现缺口：abort竞争可能遮盖“已可能打印”的不确定提示；尚未挂载核对子页时，links／reviews pending未参与空白表打印检查。两处均有定向回归，未更改旧业务写入规则。
