# 员工账号停用与考勤暂停：第193批本地交付

2026-10-06。按192边界后用户“继续”的授权，完成当前商户员工账号停用联动、负责人核验与同身份明确恢复。默认关闭，**未部署、未操作真实账号或生产服务器**。不是正式离职／再入职，也不是整体考勤计划完成。

## 已交付的实际路径

1. 企业管理的员工页：启用新流程后，原“停用／恢复”使用持久化操作编号。停用沿真实011→017→019员工更新、权限、任务交接及审计链，与考勤暂停同事务；任一步失败全部回滚。
2. 停用保存 employee/Auth、可空 worker、原启用值、原始在班尾事件及代际。在班或休息中仍可停用；不伪造下班、不改任职日期、不批改申请。
3. PIN当前凭证永久失效；目标人员和受托人员任一端的暂停代际都会使两类旧审批委托失效。恢复账号或解除暂停不复活旧PIN、未消费租约或旧委托；新凭证、授权必须另行明确签发。
4. 负责人进入“考勤配置 → 考勤暂停待核验”，明确读取当前分页名单／详情，填写核验理由并确认同一身份后解除暂停。原本未启用的 worker 仍不启用；纯受托人没有 worker 时不创建虚假档案。
5. 账号恢复与考勤恢复分开显示。新成功PATCH后仍按原号GET确认；丢响应仅核对旧号，不重复提交、清掉未知编号或猜测恢复成功。

人员列表继续隐藏所有人的Auth字段。新增 `currentAuthUserId` 仅来自同次强认证及授权成功的本人身份；不从membership编号、目标员工或脱敏快照推断当前账号。旧鉴权没有使用该可选回调的调用者保持原返回值。

详细ABI和指纹见[实现契约](employee-attendance-account-suspension-contract-20261006.md)。

浏览器使用内存认证及受限SQL读传输，不是实际Supabase登录／Next服务器／PostgREST／手机或生产压力测试。父页面不属于本包的“当前操作”读取通过原鉴权处理器，存储明确返回不可用503；未伪造成功结果，也不将此部分标为验收完成。新暂停、员工更新、考勤配置、恢复处理器／服务／SQL均真实运行。合成默认角色、看板和任务是测试前置，不代表本轮测试了企业初始化流程。

验收修复了新实现的两处问题：旧SQL接受空白规范化参数，wrapper现按同一规则解析，防止绕过已保存代际；原员工快照刻意清空Auth，改为仅取得经认证的本人Auth，避免有管理权限员工的新流程被错误阻断。另加固原状态回执读取的membership共享锁。测试夹具补齐工作区标记、唯一位置和父页面无关只读请求；没有为让测试成功而改生产业务规则。

## 数据与发布边界

- 新迁移164：五张私有表、新表索引、六个相关旧表触发器；旧员工更新及两种授权可用性入口保留OID，原函数体保存在不可直接调用的私有别名。只追加迁移，不改任何既有迁移文件。
- 锁序从merchant、考勤settings开始，再进入原任务／员工授权链，最后worker和PIN；没有employee触发器反向获取settings。锁等待上限3秒。之前151／160仍保留其原事务外并发索引安装要求。
- 两个新增开关只认精确 `1`，默认关闭。第一次联动需服务器opt-in；已有暂停代际不因关闭开关而失去保护。列表、安全恢复和最小原号读取在开关关闭时仍按各自权限工作。
- 未opt-in且没有旧代际的员工更新保留原版本检查行为。过去没有稳定操作号的成功更新不会被重放补写暂停。修改旧角色、姓名等操作没有变成新的状态操作。
- 2107份既有源／SQL基线核对：本批业务仅6个既有文件变化（员工路由、overview、Manager、AdminPanel、企业鉴权、Store），另更新迁移README。191原生runner仅增加可选后置钩子及对应契约测试，默认调用不启用193。其余为新增实现、测试和交付文档。

## 明确未完成

1. 待审申请本页显示“未核查”，不显示假零；仍去原负责人申请入口处理。服务器无法枚举其他浏览器的未知操作，不能宣称全部未结事项已经处理。
2. 新状态原号UI位于员工页。原管理人若失去员工查看权限或账号被停用，编号保留但此页可能不可达；新GET接口具备强认证原操作者最小恢复，**现有独立恢复页尚未接入这第三类编号**。只撤管理权、保留查看权时不应借恢复区重获修改权。
3. 已明确拒绝和真正未知操作目前都保留原号，查无回执不等于可以自动清号／重发；需要原操作者与负责人核验。切域、关标签页也不会迁移sessionStorage。
4. 无账号人员正式管理、离职日期／再入职、任意换绑、不可返回员工的开放班次留痕处置、工牌／实体设备实机接入验收、其他管理权限矩阵、真实账号／手机及容量试点仍未完成。25条分页协议已测，但本批未做大量暂停记录的生产容量测试。

C04仍为部分完成；固定24项盘点保持 **17项限定本地已有、6项部分完成、1项未实现，P1未完成**。下一包优先补原状态编号在撤去员工页查看权后的独立恢复入口，再逐项处理正式生命周期；不能用本批恢复功能替代离职或管理员代打卡。
