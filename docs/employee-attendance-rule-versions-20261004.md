# 考勤规则：独立候选版本账本

日期：2026-10-04，第142批。承接[第141批独立试算](employee-attendance-rules-draft-20261004.md)，新增企业默认层及指定考勤组的候选规则保存、未来登记、撤回、历史与原操作恢复。**候选版本尚未应用到实际考勤；不是完整C07或C15交付，也没有上线。**

## 本次实现

- 负责人配置页新增“企业规则版本（未应用）”；选定已有考勤组后新增“本组规则版本（未应用）”。两个入口均默认关闭、明确打开才加载。
- 仍只处理四项分钟规则：迟到宽限、早退宽限、未结束班次提醒阈值、单段已结束休息参考下限。每项明确区分继承、停用、指定整数；零宽限不是未配置，空白不是零。技术上下限不构成法律要求或推荐值。
- 保存本层草稿与登记未来版本是两个明确操作。登记只能使用已保存的草稿，且基础设置版本、组版本和企业时区必须仍匹配；成功后消费该草稿，不悄悄复制已登记版本。
- 拟生效日最早为企业当地次日；固定发布时区与该当地日的真实UTC起点。必须晚于其他尚未撤回的发布边界，不支持倒插或覆盖旧版。
- 尚未开始的候选版本可明确撤回。撤回只追加记录，原发布、原因、操作人、时间和收据保留；不删除另一个已保存草稿。
- 历史每页25条、读取第26条判断是否有下一页；按独立revision游标读取，不伪造总数或冻结快照。每条保留原操作人和原因。
- 发布、撤回都在取得必要锁后使用服务器当前时间校验，不能利用等待锁前的旧时间绕过未来限制。

这里的“继承”仅保存本层选择，不表示已经读取企业／组／个人的完整真实来源。“登记未来版本”也不表示到时自动投入考勤计算。页面明确标注“未应用”。

## 身份、恢复和旧系统边界

- 每次由当前商户负责人重新授权；同一企业的其他员工、旧负责人及其他企业不能借旧页面取得数据或继续操作。
- 锁顺序沿用商户→基础设置→指定组；新写入核对独立规则revision与上下文。两个并发请求使用相同旧版本时仅一个成功。
- 同一操作编号按企业唯一；只允许原操作人、原目标和完整原内容恢复。跨目标／换操作人拒绝，改内容重用编号报冲突。
- 客户端发POST之前将确切原编号、原目标和原命令写入当前标签页sessionStorage并回读验证。回复丢失后先GET查原收据，不自动POST、不换新编号；明确重试仍先查收据。
- 平台暂停拒绝新写入，当前仍获授权的原操作人可核对原收据。停用考勤组拒绝新草稿／登记，但允许核对和撤回尚未开始的原版本。
- 身份／目标改变、隐藏、pagehide、卸载会清除显示和未发送输入，拒绝迟到回复；待确认的已发送原操作独立保留。不承诺关闭标签页或清理站点后仍可恢复。
- 保存、登记、撤回均明确提醒本页其他未提交输入不会一同保存；取消确认保持输入且不发送请求。
- 新规则页面使用独立模态窗口，编辑期间外层表单不可误操作；Escape与关闭按钮走同一确认。上层负责人授权拒绝的epoch同时重置企业入口与考勤组内新规则入口，不重置已有组客户端。

新增127迁移仅建立两张私有表及新的service-only RPC／内部函数。操作表禁止更新、删除和截断；原始打卡、档案、归组、排班、请假、审批、工时与设置writer未改。没有改工资、角色权限、渠道、默认阈值、已有事实或生产数据。
