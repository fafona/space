# 员工考勤：故障操作API与页面调用层（216）

日期：2026-10-07。继续已批准的210范围。本轮完成三类HTTP接线和浏览器调用控制器的限定本地验收，**尚未接入实际操作页面、未部署，不是C24或P1整体完成。**

## 本轮交付

- 新增 `outages`、`outage-links`、`outage-reviews` 三个考勤API，各提供GET／POST，复用176～178现有严格协议及服务，不改SQL或旧业务成功路径。
- 真实服务入口按受验证Auth确定调用者，检查规范域、同源、当前模块资格、站点开关及速率。员工确认与负责人核验分开；不接受请求体自报身份。数据库仍负责当前人员配对、权限、版本及精确重放的最终判断。
- 请求体最多32KiB、整体读取超时5秒、严格UTF-8和重复JSON键检查；返回私有不可缓存响应，不泄露未知错误。新写关闭后仍将有权者的读取、原号恢复和精确重放交原SQL判断，而不是提前一概拒绝。
- 浏览器控制器按协议／商户／访问角色／实际Auth分开保存待确认原命令。初始化不请求；明确操作只提交一次；不轮询、不自动重发、不跨协议兜底。
- 提交前须完成原命令持久化及读回。收到回执后同时核对身份、记录、动作、版本、具体字段及原写查询＋命令的SHA-256，全部一致才清除待确认记录。
- 响应丢失后的恢复只发GET，不将恢复查询改写成POST。未知原号、授权失败、内容不一致、超时或存储变化均保留原编号。只有本实例收到精确的确定性POST业务拒绝后，才允许用户明确结束被拒的尝试；刷新、GET 404或登录失效不能证明原操作失败。
- 每次调用的网络、响应体和回执哈希共用一个12秒期限。暂停、隐藏、取消、订阅重入及存储原文变化不能让晚回包清除新记录或恢复旧显示。

178的异议／重开只豁免原协议规定的商户设置暂停及当前来源损坏检查；**没有绕过发布开关、模块资格或当前授权**。

## 接入页面时的必要边界

当前控制器不是完整React页面。宿主必须在账号、商户、角色、显示状态或组件生命周期变化时同步暂停／销毁旧实例，再显示新范围；固定actorId和异步隐藏检查本身不能独立发现任意Auth切换或两个等待点之间的隐藏后恢复。

首次声明需要新的、已授权的人员快照：workerId、employeeId、employeeAuthUserId、worker版本、employee版本及暂停代次。现有Admin人员列表和Self打卡结果字段不足；Admin配置version不是worker版本，企业employeeId不是Auth，旧声明中保存的版本也不是当前版本。owner-only任职详情不能代替self查询，nullable suspension不能未经核验就当作generation=0。

下一步需新增有界当前人员只读查询，再复用现有父页人员选择与身份生命周期保护，接登记、声明、来源关联、本人确认／异议和负责人结案表单。负责人代录与本人提交的active／暂停要求保持原176区别，不通过填默认值省略校验。当前控制器只提供GET原号核对，实际页面的人工重试与异常交接交互尚未交付。
