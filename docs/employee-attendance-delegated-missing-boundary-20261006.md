## 建议一次确认的完整业务包

当前负责人设置／撤销独立审批委托 → 受托主管仅发现范围内待审 → 读取详情和必要证据 → 明确批准／驳回 → 原编号恢复 → 员工使用既有结果／周期来源核对。

1. **独立授权、默认关闭。** 新增明确的漏卡审核权限及委托账本，不复用records.view写权限，不自动授予旧角色；只有当前负责人能授予／撤销，主管不能再转授。
2. **范围采用保存事实。** 同一委托必须同时匹配指定worker及申请保存地点，并处于授权有效期。保存受托人和目标员工的双身份；任何一方换绑都需负责人重新授权。不用当前默认地点重新归属历史申请。
3. **禁止处理自己的申请。** 受托人不能批准或驳回本人申请。负责人原有流程保持，不偷偷增加自批例外。
4. **批准会产生实际业务影响。** 新的有效批准会按现有规则进入核定工时和周期来源；不会改旧批准、生成原始打卡、修改工资或静默替换旧工时算法。这是需要用户明确批准的成功路径扩展。
5. **原操作和撤权。** 撤销、到期、离职或权限缺失后，不再读取正文或新审批。建议只让同原Auth且仍为同当前身份的操作人查询其已完成操作的最小不可变回执（编号、动作、结果等），不返回申请正文、不继续执行，也不借恢复重新授予权限。换绑身份不继承旧回执。
6. **授权与资料变化均重新核验。** 页面预览不代替事务内检查；写入核对当前授权版本、期限、申请版本、身份、地点、来源、封存和冲突。并发撤权／审批只能有确定顺序和一个有效结果，不以旧页面授权继续批准。
7. **不泄露范围外冲突。** 整段漏卡的冲突可能涉及其他地点；不能原样返回旧负责人专用证据。受托人只获取其范围内必要资料，范围外只作泛化阻断，交负责人核验。
