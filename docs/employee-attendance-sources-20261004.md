# 考勤资料：单员工、限定日期的只读来源核查

日期：2026-10-04，第143批。承接[独立候选规则版本账本](employee-attendance-rule-versions-20261004.md)，新增负责人、单员工、最多7个企业当地日期的只读来源适配及页面。**这是当前来源核查，不是正式规则应用、异常分类或历史封存；默认关闭，尚未上线。**

## 本次实现范围

- 负责人配置页的考勤人员列表新增“资料核查（只读）”。入口打开后仍须明确选择起止日期并读取，不自动查询。
- 新接口仅接受 `siteId`、`workerId`、`fromDate`、`throughDate` 四个字段；拒绝重复、未知字段及超过7个含首尾当地日期的范围。不得指定其他访问身份、写入命令或任意来源过滤条件。
- 一次只读RPC先调用既有103合并报表，重新校验当前负责人，并保留商户、设置、人员锁，再读取其他来源；不拼接多个独立HTTP分页来假装同一次完整读取。
- 分别保留原始打卡、最新已批准补正、已批准整段漏卡申报、归组生命周期、候选规则发布、排班、各状态请假及手动日历提示。申报不会变成原始事件，已取消来源不会被静默删除。
- 页面显示查询企业时区、UTC半开区间、当前设置／人员版本及服务器读取时间；来源仍保留自己的时区、编号、版本和适用的原身份信息。
- 工时来源重叠、结构损坏、授权失败或不可靠工时报表会阻止展示；归组UTC重叠则明确告警，不自动选组。未结束班次不解释为零工时。来源为空、超限或个人例外尚未接入，都不能推导为正常、缺勤或无请假。

## 来源与覆盖度边界

| 来源 | 本次选择与保留方式 | 不能据此声称的能力 |
| --- | --- | --- |
| 打卡／核定／整段漏卡 | 复用103完整来源与已有严格报表计算，保留原始和当前核定的区分；原报表上限及重叠拒绝仍生效 | 不是新工时算法、工资表或已封账周期 |
| 归组 | 按原始归组区间收集，包括后来结束／取消的历史；先取保守日期候选，再按保存的时区检查原始UTC区间。当前组投影与归组历史分开返回 | 原区间曾覆盖查询，不等于结束／取消后仍适用；当前组名称／状态不能替代原快照 |
| 规则 | 企业层与本次归组涉及的组分别返回流版本；选择查询起点之前最近一个未撤回候选发布，加上查询区间内的未撤回发布。较新的草稿不会遮掉较早候选发布 | 候选发布不等于实际生效；不执行个人例外→组→企业的正式继承，也不自动选取有歧义的组 |
| 排班 | 以UTC区间相交收集，而非仅看开始日期；向前最多24实际小时检查跨夜候选，保留取消状态和原发布来源 | 排班不证明实际出勤，也不自动生成迟到／早退结论 |
| 请假 | 按原人员编号及实际区间收集，向前最多366实际天检查包含查询范围的长区间；返回全部状态及最新生命周期摘要，显式保留原员工身份 | 不能将待审、拒绝、撤回或取消一律视为已批准；不返回请假自由文本原因，不扣余额 |
| 日历 | 企业提示及实际打卡／漏卡／排班来源涉及地点的提示；保存时区下的日期区间须与查询UTC区间相交 | 不拿当前默认地点替代历史地点；不是法定节假日库，也不自动免除排班或异常 |

每个附加来源分区最多返回100条，使用第101条候选判断超限；保守候选超限也会判定资料不足，不继续无界寻找匹配。归组／排班／请假／日历先取最多101条候选并检查数量，超限时不再逐条校验必然丢弃的内容。超限分区统一返回 `limited: true` 和空列表，不展示部分资料冒充完整。完整分区的每条来源仍独立校验；同次读取仅按“保存时区＋日期”复用UTC边界换算结果，不跨请求缓存来源或授权。规则另有两个独立上限：最多100个目标流，以及所有目标合计最多100条候选发布，不允许100×100扩张。

归组超限会同时令规则来源不足；排班超限或实际来源地点超过100个会令日历来源不足。原始／核定报表仍沿用既有总数及完整性限制，不因新页面放宽。SQL原始包与解析边界上限为1MiB；HTTP客户端另为外层响应预留少量空间，失败时不保留旧资料。

候选上限与有界返回不是已经测得的生产IO、容量或延迟保证。本轮没有新增表或索引，不声称既有数据规模下所有查询都已达成性能目标。

## 身份、时间与只读安全边界

- 可信来源检查、强认证、企业资格和限流后，由SQL每次重新确认当前商户负责人；前端传来的owner编号不能替代服务端身份。模块暂停时，仍获授权的负责人可以只读核查；关闭新功能开关或失去资格／负责人身份仍拒绝。
- 当前人员身份与有保存原身份的历史归组、请假、核定来源分别校验；不按姓名连接来源。身份变化给出人工核对警告，不能自动改写历史。既有owner报表没有提供的原身份字段也不能被臆造为完整历史证明。
- 查询边界使用当前企业时区，来源区间使用各自保存的IANA时区。按UTC检查交集及归组重叠；当地日期和夏令时边界不以固定24小时替代。
- 设置版本、当前流版本及 `readAt` 都不是不可变历史快照编号；本次锁内读取不构成后续可重放、可封账的历史来源版本。后续归组结束／取消、发布撤回或审批可能改变再次读取结果。
- 新客户端只发送明确GET；不轮询、不导出、不写浏览器存储。日期变化、隐藏、pagehide、关闭、卸载、切换企业／人员／身份，以及上层授权代次变化都会清除旧显示并拒绝迟到回复，返回后须重新明确读取。
- 新页面使用独立模态窗口，防止阅读期间误操作底层父表单。页面不保存规则、不写补正、不审批请假、不改变既有业务事实。

128只新增service-only只读RPC及私有排班来源校验函数、登记自己的迁移记录；不改原打卡、人员、设置、归组、排班、请假、规则、审批或报表writer，不回填来源，不增加旧表触发器，不授予API角色直接读表权限。
