# 员工考勤：排班与记录时间对照（第154批）

## 交付范围

在已有负责人单员工「资料核查」中增加只读时间对照。不新增接口、SQL迁移、表、索引、持久化缓存或后台任务；复用一次已获授权且通过严格解析的 Sources128 返回。原工时、审批、工资、规则绑定和打卡接口均不变。沿用资料核查默认关闭边界，本批不部署、不配置生产开关。

现有返回没有原始打卡的历史双身份、规范化后的地点，也没有153保存的整班规则绑定；排班摘要没有完整发布／取消操作时间。因此本功能不能据此正式认定排班归属、迟到、早退、缺勤或免除出勤义务。输出明确 `applied:false`、`formalReady:false`。不是“先用当前规则补算历史”的替代路径。

## 实际行为

- 原始打卡与当前核定分两个视图，互不相加。已批准整段漏卡只列在当前核定视图，保留申请和批准操作，不伪造打卡事件编号。
- 按微秒精度 UTC 半开区间求时间相交，统一3位／6位时间表示；保留原时间和各来源时区。跨午夜不用工作日期相等来配对，夏令时按真实 UTC 边界处理。
- 双向检查：一条记录跨多个排班，或一个排班对应多条记录，均为多候选，不选最近一条、不拼接成一个班次。已取消排班单列，不进候选图。
- 双方各只有一个时间候选、记录已结束、区间完整且无相关限制时，才展示带正负号的原始起止时间差。这不是迟到／早退；不采用宽限值，不扣请假或日历时段，不改变工时。
- 未结束记录保持 `endAt:null`，仅以原始资料 `asOf` 标明观察截止，不用外层 `readAt` 或当前浏览器时间补下班。零时长原始记录保留，不当作无记录。
- 跨出查询窗口、身份变化、停用人员、请假／日历来源未完整取得、排班尚未结束时，不输出完整起止差值。没有时间相交不能解读为缺勤；未来排班和进行中排班明确分开。
- 请假保留全部状态、申请／最后操作／版本及当前员工身份是否相符，只标本查询内的时间交集。已批准不代表当时已批准；不自动免除出勤、不计算请假抵扣。
- 日历按自身保存的时区转 UTC，仅关联企业范围或排班实际地点；保留已取消提示。不能由这些提示证明打卡地点。
- 原始／核定加漏卡最多100项，排班、请假、日历各最多100项；来源受限不是空列表。完整候选计算后才分页展示，不截断候选后声称唯一。
- 新纯函数不修改输入或旧汇总，输出对象与数组脱离输入并逐层冻结。新组件不发请求、不读写浏览器存储；旧父级清除资料时一并卸载。

本批通过260项相关测试，其中新增28项引擎、16项组件／静态和4项原生设施测试。覆盖微秒、半开端点、双向歧义、补正移入／移出、漏卡、未结束、零时长、跨夜、23／25小时夏令日、来源上限、身份变更、UTC边界可进入1999／2101，以及多字节地点名称。全量TypeScript、11个代码文件lint、135个迁移目录校验及15文件UTF-8／空白检查通过，新增文档8个相对链接有效；没有完整Next构建。

2. 6组实际Sources父级／处理器／服务／SQL浏览器链路：10次请求、0 POST、0外部请求、0存储调用。新区域切换不增加请求；日期、隐藏、关闭、换人／换身份／换代后的旧资料清理、390px弹窗、默认关闭及暂停状态仍通过。认证和传输适配为合成，不是真实Auth、PostgREST或完整Admin／Next端到端。

所有原公共表、函数／ACL、索引和命名空间基线恢复；只删除本次OID／owner／随机标记匹配的测试命名空间，集群、浏览器和临时HTTP已停止。不创建数据库／依赖／构建副本；系统临时目录中生成的约70KB验收PNG在目视检查后已删除，无生产访问。第一次独立截图命令使用了已改为回调的旧布尔选项，在启动前即拒绝；更正验收调用后6组全过，不涉及应用修复。
