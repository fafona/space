# 企业员工账号与运营数据完善：实施边界

## 本轮目标

本轮只交付以下四个阶段，并保持现有企业员工专用身份模型：

1. **Phase 0：安全与数据口径固化**
2. **Phase 1：员工多企业入口与邀请链可靠性**
3. **Phase 2：基于现有权威数据源的服务端活动查询**
4. **Phase 3：企业／看板当前运营概览与员工本人待办**

本轮不把“当前任务数量”包装成正式员工绩效，也不把没有员工归属字段的订单、预约或会员数据推断给某个员工。

## 当前身份与权限不变量

- 认证用户与企业成员关系是两层数据。企业权限始终由服务端根据当前 `siteId`、当前认证用户、有效员工关系、角色和看板范围实时判断。
- 同一个员工认证身份可以加入多个企业；切换企业只改变当前企业上下文，不能复用上一企业的数据缓存或权限快照。
- 同一站点同时具备企业主和员工关系时，继续采用企业主身份优先；本轮不提供“模拟员工”。
- 本轮不允许已有普通 Faolla 商户／个人身份直接融合为员工身份。现有 staff guard 仍会把出现在员工表里的用户视为员工专用 principal；在完成所有普通账号 API 的正向授权审计与 guard 重构前，融合会破坏原账号登录。
- 停用员工只撤销其在目标企业的 membership 授权，不能全局注销或删除认证用户，也不能影响其在其他企业的员工关系。
- 企业 API 每次请求都必须重新校验 membership、角色、权限和看板范围。客户端选择企业或缓存结果本身不构成授权。

## Phase 1 的安全契约

- 新增员工工作区入口，用显式企业访问令牌读取当前认证用户可访问的企业列表。
- 企业列表只返回最小展示字段；不得返回 Auth UUID、邀请 token/hash、其他员工资料或隐含权限数据。
- 企业列表响应必须 `private, no-store`。进入某企业后，各子 API 仍独立完成授权。
- 切换企业时先清空旧企业数据，再加载新企业；所有请求序列、缓存键和邀请接受去重键必须包含 `siteId`。
- 被暂停、角色无效或企业功能关闭的成员关系可以显示为不可进入，但不能加载该企业数据。
- 邀请仍以现有员工行和既有状态 `invited | active | disabled` 为权威；本轮不一次性拆表、不修改状态枚举，也不做应用层非事务双写。
- 邀请 secret 不进入日志或接口响应。接受邀请继续校验一次性 token/version、认证邮箱与邀请邮箱。

## Phase 2 的数据边界

首版活动页面只查询现有权威数据源，不新建第二套持久化“统一活动事实表”：

- 企业配置与账号管理：append-only 企业审计事件。
- 任务行为：任务事件。
- 流程行为：流程执行与确认记录。

查询必须在服务端按当前企业、员工、权限范围、UTC 左闭右开时间区间过滤并游标分页；不能下载全量数据后在浏览器过滤。任务事件需要数据库层禁止 UPDATE、DELETE 和 TRUNCATE，以保持追加式语义。

本轮不采集页面浏览、键鼠、聊天正文、IP、设备指纹或可靠退出时间。若将来增加最近活跃，只能作为近似在线痕迹，不能当成绩效或出勤。

## Phase 3 的统计口径

页面固定使用名称 **“企业／看板当前运营概览（非绩效考核）”**。

现有系统没有部门／团队实体，也没有经理下属关系，因此：

- 不出现“团队排行”“部门业绩”或经理下属统计。
- 企业主只看企业整体和授权看板的当前任务库存。
- 员工只看本人当前被分派的待办和其有权限查看的看板。
- 当前任务可展示：未完成、当前逾期、即将到期、按看板分布、当前分派情况。
- 不展示员工完成率、按时率、平均处理时长、员工横向排名、综合评分或奖惩色彩。

原因是当前任务允许多个负责人，没有 `primary owner`；任务重开会清除完成时间，截止时间也可事后修改。若直接按当前行或所有负责人计算，会重复计数并改写历史含义。

## 后续正式指标的前置门槛

正式员工任务结果指标必须另行完成：

- 可空且只作责任元数据的 `primary owner`，必须是负责人之一；不能改变现有多人协作、可见性、通知或完成权限。
- 不可变 task episode：创建／重开开始，完成结束；完成时原子快照当时截止时间、主责和实际操作者。
- 所有任务写路径统一写责任与 episode 事件，包括任务 API、清单／评论／流程、自动化、订单建任务、离职转交、角色／看板变更。
- 历史无归属数据明确标为未归因，不按当前负责人反推。
- 聚合使用独立 SQL／索引与游标，不复用最多 10,000 行的企业全量 snapshot。

正式订单、预约和会员业绩属于独立项目。订单在单一 canonical 事务写、outbox、员工操作权限、显式归属、可靠币种／支付／退款模型和数据质量 watermark 完成前，不得显示员工销售金额或净收入。

## 时间语义

- 所有原始事件保留 UTC 时间。
- 本轮当前状态概览不建立日／周／月正式指标。
- 将来任何按日统计必须先为企业建立权威 IANA 时区；不得用浏览器当前时区或固定 UTC offset 处理夏令时。

## Phase 0 写路径盘点

以下路径在未来引入主责／episode 前必须全部纳入同一事务语义：

- 任务创建、编辑、移动、完成、重开、归档。
- 清单、评论和流程执行引起的任务变化。
- 自动化创建、分派或移动任务。
- 订单创建企业任务。
- 员工停用／离职的解除负责人或转交。
- 角色、看板、列的范围变更、归档和删除。

## 本轮验收门槛

- 同一员工账号可列出并切换至少两个企业；A 企业被停用不影响 B 企业，且任何切换都不显示上一企业数据。
- 企业列表和活动查询均按服务端认证用户和企业范围过滤，跨租户 ID 枚举不泄漏数据。
- 邀请接受去重包含 token、企业和邀请版本；旧邀请、错误企业和错误邮箱均不能绑定。
- 企业审计支持服务端员工和 UTC 时间筛选；任务事件保持 append-only。
- 当前运营概览只展示可由现有数据诚实支持的库存指标，并明确“非绩效考核”。
- 新增接口具有稳定错误、`private, no-store`、类型测试、路由测试和跨企业回归测试。
- 本轮变更不触碰普通 Faolla 身份融合、员工排名、订单金额业绩、导出或监控式行为采集。
