# 考勤资料保留与单条保全：第227批

## 批准范围与交付边界

用户对第226批提出的具体范围回复“继续”，本批仅实现三类资料的默认未配置期限、只读到期试算和单记录保全／解除。未授权或实现自动删除、脱敏、关联传播、工资计算、生产数据修复或部署。

三类为原始打卡事件、定位结果摘要、固定周期归档。期限为空表示未配置，不补写法定默认值；配置天数为1～36500。事件与定位摘要从原事件接收时间起算，归档从保存时间起算，以每天86400秒计算；到期与保全状态独立展示。到期不表示可以删除，解除保全也不是删除许可。

本批不使用现有其他“保留天数”配置代替这套独立政策，也不修改原打卡、审批、工时、周期正文或历史身份。保全只登记选中记录，不自动覆盖关联记录。原始事件中的`web`／`kiosk`字段只按原保存来源展示，不宣称已证明更细的实际打卡方式。

## 实际入口与安全设计

- 企业考勤负责人页增加“资料保留与单条保全”，独立懒加载。打开不自动请求业务数据；由用户明确读取设置、人员、周期、记录和历史。
- 人员列表每页25条，包含停用人员；事件／定位试算按UTC日期范围和保存的人员键查询，最多31天、100条，超量要求缩小范围。归档按选定的单人员、精确起止日期的已有周期查询。历史记录也可按已知记录编号核对，不把当前绑定身份补写为历史身份。
- 当前商户的规范负责人可管理本商户历史资料，包括离职、换绑和负责人交接之前的记录。原操作回执仍限定原操作人；新负责人不能冒领旧人的待确认操作。
- 新迁移182只增加两张追加式元数据账本和八个新函数，不替换旧函数或改写旧业务表。新表RLS与私有权限、不可更新／删除／截断保护、完整命令和来源指纹校验保持关闭式拒绝。
- 新写入要求当前版本一致，单条保全另核对来源指纹；两账本共享操作编号冲突检查。相同原操作可精确重放，改内容、改对象或跨账本复用编号拒绝。
- 客户端先保存作用域明确的原操作编号再发一次POST；丢响应、超时或查询暂无回执时保留编号，只显式GET核对，不自动重发。只有明确且状态匹配的服务器拒绝才允许用户结束本地尝试。
- 关闭新写后仍可按当前合法身份核对原编号。切商户／负责人和页面隐藏隔离旧响应；隐藏清空当前显示与未提交元数据编辑，待确认编号保留在本标签页会话存储。首次隐藏挂载后显示时也只恢复本地状态，不自动请求。
- 服务端验证真实认证、规范来源、同源、资格和限流；客户端与服务端请求均有字节、时间和结构上限，响应不缓存。

独立开关默认关闭：`NEXT_PUBLIC_FAOLLA_ATTENDANCE_RETENTION_ENABLED`、`FAOLLA_ATTENDANCE_RETENTION_ENABLED`和显式`FAOLLA_ATTENDANCE_RETENTION_SITE_IDS`名单。未修改任何部署环境或商户开通数据。迁移182显式依赖061／072／135／149及其前置，并不依赖181故障关系能力。
