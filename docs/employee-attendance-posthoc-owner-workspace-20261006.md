# 第205批：负责人事后采用入口与当前依据只读核对

2026-10-06，继续执行已批准的[203范围](employee-attendance-posthoc-adoption-boundary-20261006.md)，承接[204基础](employee-attendance-posthoc-foundation-20261006.md)。本批接通负责人实际操作页、原编号恢复及保存来源／当前请假的只读预览。**不是正式新异常决定、员工结果或周期闭环已完成，也没有部署。**

## 已实现的实际路径

- 原人员资料核查→排班覆盖→[异常工作区](../src/components/enterprise/MerchantAttendancePlanExceptionWorkspace.tsx)增加负责人“事后来源采用／撤销与历史”入口。沿用原身份／API／授权代次卸载和日期／关闭／Esc离开守卫，不给员工调用负责人接口。
- 新[采用工作区](../src/components/enterprise/MerchantAttendancePlanPosthocWorkspace.tsx)明确选择完整来源、最多10项、有理由保存或撤销。既有选取不自动回填成新选择；空组必须明确确认，不表示准点、请假批准或已结案。撤销使用保存操作指纹，不要求已损坏来源重新可用。
- [独立客户端](../src/lib/merchantAttendancePlanPosthocClient.ts)使用商户＋真实owner Auth＋人员＋排班的精确sessionStorage键，只保存小命令、不存证据。先持久化并重读精确字节，才发送一次POST；收到匹配原命令、原号、双身份的收据后才清除。
- [实际采用API](../src/app/api/merchant-enterprise/attendance/plan-posthoc/route-handler.ts)严格查询／请求体、可信来源、真实认证、限流、私有no-store；SQL仍最终验证负责人和历史双身份。独立精确商户新写开关默认关闭；关闭新写不提前挡住历史GET或原号POST重放。
- 提交结果不明时只能核对原号；明确重试先GET，若精确404，再重新授权读取当前双身份，才按原号、原内容POST，不换号。错误、超时、身份变更或存储变化保留原意图。
- “停止本地跟踪”只在明确核对后清本地意图，**不取消请求、不承诺原请求永不成功**；页面和确认框都说明旧请求可能稍后成功，必须再读服务器历史。
- 当前来源读取、预览读取、写回执分开，不混用不同读时点。隐藏／退出／换目标立即清正文和输入，旧异步回复不能重新曝光资料；不自动查询、不轮询、不自动重发。

## 新的只读核对能力

[172迁移](../scripts/supabase-migrations/202610060172_merchant_attendance_plan_posthoc_evaluation.sql)仅新增2个函数，没有表／索引，也没有替换159正式来源、170决定或158周期函数。

- [严格评估协议](../src/lib/merchantAttendancePlanPosthocEvaluationContract.ts)保留完整旧v1/v2依据，包括工作安排；分别保留171当前保存操作、选择时端点快照、固定140引用、逐项当前观察和真实请假当前头。
- 每个采用来源按不可变班次ID／漏卡根点查，不因修订时间移出排班窗口就消失。后继批准只作为当前观察，不自动代替原采用。自己的独占投影须仍指向同一采用头；未知、变代或不完整均不能成为正常依据。
- 固定规则按保存140操作取原文／SHA和历史身份，不拿最新规则替换。原关联班次中途地点不一致、期外待审补正／漏卡修订这些紧凑端点无法证明的阻断，由锁内171事实保留，不能被新预览漏掉。
- 请假先按准确UTC相交取有界集合，再核验历史employee/Auth和当前审批头。保留取消、撤回、拒绝与待审，旧来源已有不完整标记时仍未知，不借新查询消除旧未知。
- SQL返回完整事实及canonical原文／SHA；[Node服务](../src/lib/merchantAttendancePlanPosthocEvaluation.server.ts)核验后去掉原文。[GET-only API](../src/app/api/merchant-enterprise/attendance/plan-posthoc-evaluation/route-handler.ts)仅发布8项事实，不发布可被信任使用的派生候选或正式结论；浏览器再严格解析并独立计算。
- 负责人可明确点击“核对保存来源与请假（预览）”。页面展示保存／当前版本差异、请假覆盖、剩余要求、工作重叠及首末候选，列表最多10项一页，本地翻页，不额外请求。
- `not_active`、`blocked`、`required`、`not_applicable`分别显示；全假无实际工作时的无需评价只是预览态，不是`cleared`、全勤或伪造上下班。实际工作与请假重叠仍阻断。关闭写入不阻断授权读取。

本批派生计算在严格TS读取侧，**未来正式决定必须在SQL同事务重算／验证，不能信任本预览或浏览器回传**。
