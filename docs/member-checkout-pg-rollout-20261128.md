### 哪些权限要核对

新只读检查只输出固定问题编号／数量，不读取客户行、函数正文、密码或凭据。核对三种结算角色的权限属性、关联角色和固定入口授权；新 LOGIN 仅有显式 CONNECT、`public` 用法与指定结算函数调用能力，不能转授权。其他对象检查包含永久 schema 的创建权限、表／视图／外部表的表级或列级权限、序列和非系统 schema 中可用的其他函数。默认授权与内置基线区分，不能把“没有新增默认授权”当成“未来对象不会自动向 `PUBLIC` 授权”。上线后有新对象或授权变动，应重新核对。[PostgreSQL 15 的权限与默认授权](https://www.postgresql.org/docs/15/ddl-priv.html)

核验通过仍不等于网络隔离。其他数据库的 SQL 层 CONNECT、当前库 TEMP、不可达 schema 的函数授权以及普通 invoker 触发器授权分别记录。临时对象和系统函数没有被此检查全部禁止；普通 invoker 触发器不提权。正式目标还要独立证明认证规则仅接受指定数据库、角色、私网来源和 TLS，并审核实际扩展与其他库；不以全局撤销 `PUBLIC` 让核验变绿。

## 正式接入顺序（任一项不符即停）

1. **先做同候选联测。** 保持已验证 PG 候选及回退版源码／锁／构建身份固定，用合成数据和真实 PG15.8／Auth／Next 测试下面的保留路由、旧入口写保护及未知结果；以数据库已知状态判断，不仅看 HTTP 200。终止自有测试服务，保留报告；不扩建签发系统或修改已验证 SQL。
2. **只读核准目标。** 重新确认此次获准连接的实例、数据库、主库／恢复状态、登记／目录、私网来源与 CA／证书 SAN。现候选只接受指定格式的私有 IP 和验证完整 TLS 的配置；域名、证书不匹配或只有公网路径则停止，不关闭验签、不开放公网数据库。依据实际 worker 数、每实例最多四个应用连接、角色连接上限及峰值剩余容量核准小流量预算。开发测试不证明生产容量或宿主 root 隔离。
3. **先获取可恢复备份。** 由获准的既有备份流程覆盖数据库（含原子预约、订单、会员、积分／券／库存、旧 pending、新账本、迁移登记及角色／ACL 等集群级元数据）、安装凭证／定位文件、应用与路由配置、两版构建和静态资源清单。记录恢复点、存储位置、校验摘要、恢复责任人、预计数据损失与恢复时间；密钥由既有保管机制管理，不写入证据或日志。选独立隔离环境验证能恢复和读回原单，不能只检查“备份文件存在”。
4. **关着业务门禁安装。** 另绑定准确生产安装来源／登记而非照抄 CI 登记；保留登记和目录漂移拒绝、事务及安装互斥、前后身份、原提交独立只读确认。最小业务授权仅专用 `faolla_checkout_runtime_login` 的必要 CONNECT／schema USAGE／固定 dispatcher EXECUTE；核对有效权限（含 PUBLIC、列 ACL、成员与默认授权），不得把执行角色、BYPASSRLS 或表操作权交给网站。身份／授权混入未审范围则停止，不为让检查通过修改全局权限。实际事务未提交走原事务回滚；提交后只确认原结果，不自动重放、不删表、不回滚迁移，不用备份覆盖活库。如确需结构修复，只做另行批准的向前修订。
5. **隔离启动再放量。** 生产候选、原普通服务、稳定回退及已验证原单服务保留；用无维护代次检查通过后再批准切流／开单。先以管理只读、拒绝写入、普通登录与原业务不变验收「安装但未开放」，再批准第一笔指定试点真实交易。观察通过才允许后续扩围。暂停、路由回退、紧急撤权是三项不同操作。

## 停新单和保留原单的路由矩阵

下表是待验收边界，不是已经上线的分流配置。售后服务必须由仍识别新账本且能用已验收 PG 身份的候选承接；旧 ENV 单测通过不代表现场有可用／获准的 JWT。保留路由必须保持规范域名、会话和原授权检查，且在候选不可用时明确拒绝，不能改投旧收银。

| 用途 | 正常停新建／普通流量回退后的处理 | 已有证明与待验收 |
| --- | --- | --- |
| 普通页面／登录与非结算入口 | 仅交给已核准的旧版；保留原 Cookie 和两版不可变资源。原单页面依赖的普通身份接口仍须正常 | 原夹具验证选定页面和身份；本次准确部署目标及其路由未确认 |
| `GET /member-checkout/{site}/resume`；`POST /api/member-checkout/history/{pending,recover,retained}` | 只在批准站点保留原单恢复页和三个分别列明的只读接口。独立 `HISTORY_READ_SITES`；pending 无记录不等于提交失败，recover 只按原 nonce，retained 只列历史 | 原夹具未留整组；用 PG 验证跨设备 pending、丢回复原号找回、列表与错主体拒绝。读取不得 ack、重新下单、消耗购物车或强行清未决状态 |
| `GET /api/member-checkout/resource` | 按原参数／原账号读取，走独立 history read 分支；不得暴露别的账号或商户 | 旧传输已通过保留；接到准确 PG 候选与回退代次仍需联测 |
| `GET /member-checkout/{site}/service/{operation}`；`POST /api/member-checkout/original-service/{review,cancel}` | 只保留已审批站点的原单页和精准 review／cancel；独立 HISTORY_READ／ORIGINAL_SERVICE 应用门禁、原单服务数据库门禁保留。取消只执行原政策允许的积分／券／库存返还，不是现金退款 | 旧双版本有一次性返还／取消回复丢失证据。PG 组合需重验：已提交回复丢失→重新读原单→旧 review 拒绝→新 review 安全读回取消结果、不重复返还 |
| `POST /api/member-checkout/single/points/submit` | 优先由原单只读恢复替代。仅当真实客户端必须重放、且关闭 DB 创建后准确原请求能读回、任何新 nonce 均不能写入，才保留此一入口。不能关掉它需要的应用前置开关却宣称提交重放仍可用 | 旧传输在 DB 创建关、应用门禁仍开时验证原号重放和新 nonce 拒绝。本次若不保留，应有已打开页面遇拒后可到 resume 的已验收路径 |
| 新建／扩围：preview、其他 submit、start、cart、on-site、bound-submit、intent 写入、`acknowledge`、`register-retained`、`close-unused`、收款和配置写 | 关闭数据库新建门禁；外层精确拒绝其余新功能，不走旧应用。旧 `/recover`、普通结果页等依赖购单门禁，不列为独立售后默认入口；确需兼容在途浏览器时，必须补精确只读接续验收，不能开放整个前缀 | `history/*` 与旧 intent／关闭引用能力不是同一组，禁止为增加查询而顺带开放写入。不把页面隐藏当成旧脚本已停用 |
| 原业务中的预约／订单及旧收银 pending | 旧版不得把新账本关联记录当普通单任意改期、改价、取消或恢复；只要求未关联原业务继续成功、原 pending 字节保持。须验证正式适用的原子存储和关联／创建保护触发器仍生效 | 安装层已验证合成旧 pending 不变、旧普通入口有数据库保护；准确旧构建＋PG 回退联测仍须用旧入口尝试改动并验证拒绝及账本不变。不成立则继续保留兼容写入口或不开放试点 |

**先停新建，再切普通流量。** 确认数据库创建旗标已关闭，并核清在途写入／锁与未确认结果；不以超时当回滚、不换 nonce、不自动补扣。候选售后、静态文件、老版普通健康均通过才推进新代次；失败维持原路由，或只保留已验证的原单路由并报告。紧急撤销专用 PG 权限会同时切断售后，不得当成日常停卖；若不得不撤，先保全状态并记为原单服务不可用，恢复只用重新核准的受限通道。切回候选必须再确认原账本与已完成取消不被重做，恢复开单另经批准。

## 下一次只需批准什么

本地验证完成后，若需线上事实，先单独批准**一次**现有受信通道的只读元数据核对：目标和基线、权限投影、私网地址／证书交付可用性（不读密钥）、预算、备份覆盖及回退构建身份；原已消耗许可不复用。只读、范围及超时固定、证据私有，未知保留未知；不读客户行、密码、密钥、完整环境，不安装、不调权限、不切流。

之后依次另行确认：在批准位置备份并隔离恢复；只安装已绑定的新增结构与受限账号（创建门禁仍关闭）；带原单保留验收的候选切流；单商户真实试点开关。每次只请求对应步骤所需权限，本清单不预先授予下一步。
