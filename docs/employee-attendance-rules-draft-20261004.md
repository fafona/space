# 考勤规则：独立草稿试算与正式接入边界

日期：2026-10-04，第141批。本批只完成无持久化的规则继承试算核心、独立组件及本地验收；没有接入企业后台菜单、保存／发布接口、数据库或正式异常判定。不是已生效的考勤规则功能，C07／C15不因此改变固定完成状态。

## 本批交付

- [纯试算核心](../src/lib/merchantAttendanceRuleDraft.ts)：逐字段按个人假设→组假设→企业假设解析；每项输出来源与实际经过的判断层级。
- [独立试算组件](../src/components/enterprise/MerchantAttendanceRulesPreview.tsx)：四项规则在同一行比较三层假设，显式点击试算；修改任何输入立即清除旧结果。个人假设不冒充已审批例外，组假设不冒充真实归组。
- `继承`继续查找；`明确停用`停止回退；`指定分钟数`要求明确整数。全部继承为未配置，不能默认为0或已停用。
- 不预填任何公司或法定阈值。四项输入为迟到宽限、早退宽限、未结束班次提醒阈值、单段已结束休息参考下限。数值范围只是技术上限，不是推荐值或劳动规则。
- 拟生效日使用明确IANA时区，须是尚未开始的未来当地日期；使用现有时区算法取得真实UTC起点，拒绝跳过的民用日期。浏览器默认时区、UTC日期或固定24小时运算不替代当地日期。
- 输出为独立、深冻结的结果；不能随后改输入对象而悄悄改变试算来源。严格拒绝缺项、未知项、隐式数字、非法原型和访问器。
- 草稿只在组件内存中存在。转入后台／pagehide同步清除，返回须明确重新开始；切换时区、卸载和刷新也不会恢复。没有浏览器持久化、网络保存、导出或发布。

试算的`checkedAt`只是输入校验时刻，`effectiveAt`只是拟生效日边界；它们不是服务端时钟、发布收据、授权或历史计算快照。组件尚无正式用户入口；只从本批隔离验收fixture加载，不能声称用户已能在现网使用。

## 为什么不能直接复用已有组和列表判定异常

| 已有资料 | 查明的真实边界 | 正式接入要求 |
| --- | --- | --- |
| 归组记录 | 日期标签含首尾；同人跨组也不允许标签重叠，但不是UTC有效区间。结束／撤销可以改变当前投影，不能作历史as-of。 | 明确时区与UTC半开区间、唯一匹配和历史来源快照；冲突不得取最新一条或悄悄降级。 |
| 时区 | 原始打卡已有时禁止改变企业时区；仅有归组／排班／请假时不能假定时区不变。 | 新版固定发布时区与UTC边界，不用当前时区重解释旧标签。 |
| 设置版本 | 基础设置版本会因多种配置更新，分组另有独立revision。 | 规则账本使用自身版本；基础版本只作上下文校验，不覆盖原网页打卡、带薪休息等设置。 |
| 请假列表 | 摘要没有workerId，负责人列表无人员／日期过滤，只取首25条不完整。 | 不按姓名联接；需要有权限、按人员日期限定且可证明完整性的读取。 |
| 日历 | 企业或单地点分开查询；节假日／停业日只是提示，不是休息日或停工授权。 | 独立提示，不自动取消排班、免除异常或拒绝打卡。地点核对须有实际来源，不能拿当前默认地点代替。 |
| 排班／工时 | 排班按开始日查询，可跨夜；没有结构化休息日标记。原始、核定和漏卡申报是不同来源。 | 先明确比较来源与范围完整性，保留分段、跨夜和精度；无排班不等于缺勤。 |

具体例子：A组归属按洛杉矶时区至10月4日，B组按马德里时区从10月5日；日期标签不重叠，但按各自时区转UTC可重叠9小时。因此“已有标签没有重叠”不等于“某个打卡时刻必有唯一规则”。

## 下一项实际交付：独立规则版本账本和负责人读取

正式落地应先完成下列一个有限工作包，不先接旧打卡writer，也不把试算当发布：

1. 确认首版规则范围与生效策略。已向用户提出个人例外→组→企业、最早次日生效、只提醒不扣工资／造打卡／阻止真实打卡／追溯修改的范围问题；本批记录不把未收到的回复当批准。
2. 独立负责人草稿／发布账本：当前负责人重新授权，独立revision、原因、操作者、发布时间、时区、UTC边界和不可变操作收据。新增RPC不借用旧配置保存来更改已有成功设置。
3. 按既有锁序串行核对上下文；等待锁后重新检查未来条件。相同操作者、编号和内容才能恢复原收据；平台暂停拒绝新发布，当前有权者可核对原操作。
4. 明确归组结束／撤销与规则来源快照的关系，以及已开始跨夜班次的规则归属。只限制规则未来生效，仍不足以防止当前归组投影回溯改变历史计算。
5. 首个读取适配器限负责人、单员工、明确日期范围；统一来源版本、身份、授权与覆盖度。任何缺页、范围截断、归属冲突或缺来源都输出“资料不足”，不是正常／零／无请假。
6. 规则版本和来源准备完整后，再提供带证据的异常核查。触及既有打卡、补正或审批成功写入路径之前，说明具体变更及风险并取得批准；不因“继续”自动更改旧事实或工资口径。

异常联动尚须细化：原始与核定事实如何分别比较、宽限的临界值、单段／每日／班次间休息的区别、批准部分请假是否改变预期到离时间、休息段是否算出勤覆盖。当前四字段草稿不暗中决定这些问题。个人已审批例外模型、渠道／地点授权、审批职责、通知、完整周期冻结均未包含在本批。
