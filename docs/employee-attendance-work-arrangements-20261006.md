# 出差／外勤／远程工作安排：首版本地交付

日期：2026-10-06，第187批。按第186批范围后的用户“继续”批准实施。**限定功能包本地完成，默认关闭，未部署；整体考勤P1未完成。**

## 交付的实际使用链

员工考勤页“我的出差／外勤／远程申请” → 读取首页 → 选择类别、当地起止及理由 → 预览时间／重叠 → 明确提交 → 当前负责人审批 → 员工查看结果及不可变历史。

- 三类工作安排使用独立申请、追加操作及政策账本，不混入请假。
- 待审可撤回或驳回；批准后只能追加有理由的取消。员工不可自批；当前负责人可以驳回自己的申请，但不能批准自己。
- 默认允许最近30个企业当地日的补申请；负责人可独立设置0–365天，并保存每笔申请采用的政策版本。不是法定期限，也不借用请假或补正配置。
- 保存企业时区、UTC起止、员工及Auth双身份。不存在的当地时间拒绝；重复时间要求指定偏移。历史展示／归档不使用当前Intl重新解释旧时区。
- 与本人工作安排、请假、排班重叠时展示关联资料；批准需明确确认重叠并提交理由。再次审批前重新计算冲突指纹，防止审批旧页面。
- 批准只认可安排，**不是实际到岗、实际工时或自动免除迟到／早退**。不生成打卡，不改变工资、假期余额或旧工时，不阻止真实上班／下班。
- 未知提交结果保留原操作编号，只GET核对，不自动重发或换号；明确证明整笔拒绝的有限错误才允许清理自己的待确认编号，重新读取后再操作。

## 与已有功能的接入

新增156–159候选迁移，旧迁移文件不改：

1. `156`：三张独立账本表、私有校验／上下文／冲突函数及仅service_role可执行的新RPC；表对API角色不开放直接读写。
2. `157`：权限目录接受`attendance.self.work_arrangement`，依赖企业查看及本人考勤查看；不自动授予存量角色。
3. `158`：周期来源保留旧collector，相关安排非空时使用显式`attendance-period-source-v2`并保存完整历史；为空时返回原v1。相关待审阻止封存；批准、取消等来源变化要求重新送审确认。旧归档不回填当前安排。
4. `159`：异常核对新增显式v2依据和操作引用；待审先处理，已批准安排仍由负责人明确核定异常，不能自动豁免。旧人工决定和v1读取保留。

新申请、批准和取消执行原150封存门禁。周期与安排使用一致锁顺序，避免封存检查后插入新申请。已封存相关区间必须明确重开；不自动解除封存。

实际本人／负责人父页面各增加独立入口和离开保护；不把安排待确认状态加入旧打卡／安全下班阻断。默认关闭时不发新列表请求；已有待确认编号仍可进入只读恢复。
