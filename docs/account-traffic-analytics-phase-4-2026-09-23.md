# 账号访问分析：第四轮收尾与发布边界

本轮状态：开发与本地自动验证，不是已部署。未修改线上代码、数据库、配置或已有业务数据。服务器只做只读检查。

## 新增实现

- 预约、订单、入会、投票在对应服务端持久化成功后调用独立计数器。按账号/模块/真实业务记录生成确定性事件 ID，重复调用不增数；公开采集接口不接受这些成功动作或服务端 UUID 类型。
- 写入不被业务处理器 await，限时两秒、失败隔离、默认开关关闭；DNT/GPC/已知机器人跳过。超过十分钟的旧记录重开不回填成今天的新结果。只有分析计数，不改业务记录。
- 成功结果单列，名称明确为预约创建、订单创建（不是付款）、会员加入、投票提交。不是访客级漏斗、净成交或撤销后余额；后台与 CSV 明示统计可能漏报、业务账本才是最终依据。
- 独立活动/投放位置：超级后台授权及同源校验后签发含随机活动 ID、名称、账号和媒介的签名标签。仅同一归属账号的事件接受活动；伪造/跨账号标签不改变归属。
- 活动链接是用户主动生成的独立链接，不覆盖名片/旧二维码。签名不自动过期，轮换统计签名密钥会使旧活动标签失效；不提供活动管理列表/撤销，需保存生成的链接。同名再次生成是独立 ID；活动只在有采集记录后出现在报表中。
- `/card/...` 的两个现有投票 307 跳转分支只透传合法、限定长度的统计标签；无标签时目标 URL 完全不变，不复制邮箱等任意参数，不改保存的目标。
- 个人名片：在已知个人归属和精确存储 shareKey 匹配后签发普通/分享联系卡采集资源。查询失败不阻断页面；增加超级后台个人账号的访问分析入口；未建站商户也可按账号 ID 打开已有名片分析。
- 完整 CSV 使用一个完整范围 SQL 快照，导出所有匹配对象，不再受 50 项页面分页限制；校验实际行数等于对象总数，否则拒绝产生截断文件；25 秒服务器/30 秒浏览器超时，不冒充异步大数据任务。
- 新增迁移 051：活动维度、成功动作、私有完整导出函数，并更新汇总和清理守卫的维度。049/050 仍需先应用，未处理旧业务表数据。
